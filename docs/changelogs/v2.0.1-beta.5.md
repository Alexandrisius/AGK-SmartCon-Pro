# SmartCon v2.0.1-beta.5
**Дата релиза:** 28 июля 2026  
**Предыдущий релиз:** 2.0.1-beta.4 (20 июля 2026)  
**Платформы:** Revit 2019, 2020, 2021, 2022, 2023, 2024, 2025, 2026  
**Статус:** Pre-release (beta) — предназначена для тестирования
---
## 🔥 Главное в этом релизе
Релиз состоит из двух крупных волн. **PipeConnect: элемент-wise цепь и LockNetwork** — цепь собирается по одному элементу за раз, свежеприсоединённый элемент становится активным динамиком для вращения/ресайза, а сеть можно заблокировать в жёсткое тело одним чекбоксом. Плюс навигация вида прямо из модального редактора, детерминированный цикл коннекторов и большой рефакторинг привязки размеров через `MEPFamilyConnectorInfo` (ADR-057), ускоривший чтение параметров семейств в 6–7 раз. **FamilyManager: единый движок актуализации базы (ADR-054)** — вместо цепочки диалогов миграции одна команда «Обновить базу», открывающая каждый файл ровно один раз. Плюс подсистема фактов о семействах (ADR-055), контент-хэш v3, инвариантный к языку Revit, и волна исправлений стабильности: утечки памяти, дедлоки, падение Revit на net48 и логи по 74 МБ за сессию.
**Топ-7 изменений для пользователя:**
1. **Цепь собирается поэлементно** — каждый присоединённый элемент сразу становится активным: вращайте и меняйте размер вокруг оси его родительского коннектора; панель показывает текущий элемент цепи
2. **«Блокировать» (LockNetwork)** — сеть ведёт себя как одно жёсткое тело: «Подключить всё» двигает её целиком без компенсаций, ручной «+» присоединяет as-is, вращение крутит всю герметизированную сеть вокруг граничного коннектора
3. **Просмотр и зум из редактора** — кнопки [-] [Просмотр] [+] в нижней панели: зум к активному коннектору с компенсацией перекрытия диалогом, точка интереса не уезжает за Topmost-окно
4. **ConnectAll больших сетей больше не «вешает» Revit** — тяжёлая перезагрузка размеров выполняется один раз в конце обхода, а не на каждом элементе; цепь из 50 элементов проходит за секунды
5. **Одна кнопка «Обновить базу» в FamilyManager** — единый движок актуализации вместо нескольких диалогов миграций: критические задачи блокируют базу до обновления, опциональные показывают янтарную точку (ADR-054)
6. **«Тип детали» и Revit-категория в свойствах семейства** — у фитингов видно Part Type официальной RU-локализацией Autodesk; Revit-категория показана и для загружаемых, и для системных семейств (ADR-055)
7. **Коннекторная привязка размеров без геометрии (ADR-057)** — отвод с шаблоном 45°, поставленный на 90°, больше не теряет список DN из lookup-таблицы; чтение параметров семейства ускорено в 6–7 раз

## ✨ Новые возможности
## PipeConnect
### 🔗 Элемент-wise цепь с активным динамиком
- Цепь присоединяется **по одному элементу** (плоская BFS-очередь) вместо пакетов уровней; свежеприсоединённый элемент становится активным динамиком — цель вращения/ресайза/вставки вокруг оси BasisZ родительского коннектора
- Состояние фитинга/редуктора по каждой точке подключения слотировано и восстанавливается при откате; автоматический откат при неудачном присоединении — очередь никогда не продвигается по «оторванному» элементу
- Новая информационная панель показывает текущий элемент; шаг вращения по умолчанию — 45°
- Connect предупреждает о неподсоединённых элементах цепи: «присоединить всё и соединить» / «соединить как есть» / «вернуться» (TaskDialog с command links)
### 🔒 LockNetwork — сеть как жёсткое тело (#165, #167)
- Чекбокс «Блокировать»: сеть = одно жёсткое тело для ConnectAll (без компенсаций и ресайза); ручной «+» присоединяет as-is (без редуктора и поглощения длины трубы, с предупреждением о несовпадении DN)
- После жёсткого соединения вращение крутит всю герметизированную сеть вокруг BasisZ граничного коннектора; cross-рёбра восстанавливаются после вращения
- **Мгновенный toggle для труб**: OFF→ON откатывает поглощение смещения (точная геометрия трубы/flex до Init), разрывает герметизацию и применяет жёсткий перенос — сеть остаётся отсоединённой, дальше идём поэлементно as-is. ON→OFF возвращает поглощение и повторяет герметизацию
- **Унифицированная модель Lock** (#167): один механизм снапшотов для всех типов элементов — ON восстанавливает baseline (откат absorb/resize/ChangeTypeId), жёстко выравнивает к upstream-точке, возвращает DN фитинга и вставляет редуктор при несовпадении DN; OFF убирает редуктор toggle и возвращает скомпенсированное состояние
### 🖥️ Навигация вида из модального редактора (#166)
Модальный редактор блокирует навигацию вида — добавлен блок [-] [Просмотр] [+]:
- «Просмотр» зумируется к **активному динамическому коннектору** (радиус 0.75 м) — следует за переключением активного динамика при работе с цепью
- Зум +/- масштабирует вокруг центра видимой зоны — точка интереса никогда не уезжает за Topmost-диалог
- **Компенсация перекрытия**: прямоугольник зума смещается так, чтобы цель попала в максимальную видимую полосу вида, а не за окно диалога
- UIView-зум не открывает транзакцию — безопасно в модальном контексте команды
### ⚡ Производительность больших сетей
- **Rigid move fast path**: когда границе нужен один общий перенос, весь остаток сети двигается ОДНИМ телом (MoveElements/RotateElements) вместо поэлементного перебора
- **Bulk ConnectAll**: тяжёлый dynamic switch (перезагрузка размеров из lookup-таблицы) выполняется ОДИН раз в конце обхода вместо каждого элемента — ConnectAll цепи из 50 элементов больше не «вешает» Revit на минуты
- Кэш connector proxy в тихих проверках
### 🔄 Устойчивость петель (cross-edges)
- Восстановление петель: прямое соединение при совпадении DN, поглощение длиной трубы на больших зазорах, редуктор + поглощение при несовпадении DN (каскад может дать концам петли разные DN при ветвлении через редуктор/переход, ADR-053) — трубы и тройники больше не остаются отсоединёнными после ресайза всей сети
- Герметизация восстанавливает петлевые рёбра ВСЕХ уровней остатка, а не только граничного; осиротевшие редукторы удаляются при неудачном восстановлении
- Обратимая ранняя герметизация (ADR-052): auto-seal на границах уровней и как fast path ConnectAll; UnsealIfSealed разрывает seal перед любой правкой или откатом
- Фильтрация self-edges (AllRefs трубы включает её же дальний коннектор); GlobalYSnap применяется ко всему набору вращения
### 🎯 Детерминированный цикл коннекторов (#163)
- Порядок перечисления ConnectorSet в Revit API случаен — теперь гарантирован детерминированный геометрический порядок (X↑, Z↓, Y↑, tie-break Connector.Id) через чистый `ConnectorOrdering` в Core
- Ключ сортировки инвариантен к жёстким трансформациям: family-local координаты для FamilyInstance, проекция на ось для MEPCurve — порядок цикла стабилен между обновлениями, даже пока редактор переставляет элемент
- **Корневой коннектор следует выбору цикла** — раньше SwitchToPoint(0) восстанавливал дефолтный коннектор сессии, игнорируя выбор пользователя, и ConnectTo шёл по неверному коннектору (тройник «прыгал» на отводной порт)
- ValidateDirectBranch перевыравнивает динамик к статику при не-антипараллельном BasisZ вместо простого предупреждения (предотвращение авто-ориентации Revit)
### 📐 Сброс вращения через BasisY свободного коннектора (#160)
- Раньше сброс мерил `FamilyInstance.GetTransform().BasisY` (игнорировал flip'ы, параллелен оси вращения на отводах Kan-therm) и целился в горизонтальную проекцию глобальной оси: клапаны ложились вверх ногами (180°), отводы не вращались вовсе
- Теперь сброс выравнивает **BasisY свободного коннектора** (Z×X, направление высоты семейства) к проекции мирового «вверх» на плоскость коннектора: никогда не вырождается, учитывает flip, единственная целевая ориентация; вертикальные оси откатываются на сетку плана
- Плюс: привязка BasisX к глобальной сетке (унифицирована для attach и вращения в редакторе), диагностика вращения в логе, исправления знаков в snap-дельтах (правило правой руки), кнопка сброса в редакторе
### 📏 Привязка размеров коннекторов через MEPFamilyConnectorInfo (ADR-057, #161)
Замена legacy-матчинга коннекторов проекта к ConnectorElement'ам семейства по геометрии (порог score 0.99) на прямой API: `Connector.GetMEPConnectorInfo()` → `GetAssociateFamilyParameterId`:
- Геометрический матч ломался, когда instance-параметры (угол отвода, DN) отличались от шаблона семейства: отвод с шаблоном 45°, поставленный на 90°, набирал score 0.7071 и **молча терял lookup-таблицу** (пустой список DN). Теперь полный список DN доступен
- **CTC-матчинг через IsPrimary + порядок индексов** — без геометрии: якорь IsPrimary (точный для 2-коннекторных фитингов) + порядок индексов коннекторов (совпадает с порядком создания, Tammik); проверено на отводах и ниппелях Kan-therm
- **FamilyFormulaCache**: снапшот параметров семейства (имена, формулы, IsInstanceByName) строится один раз на семейство на документ (один EditFamily вместо 6–7); таблицы размеров читаются из project-документа (официально поддержано); EditFamily остался только для записи CTC
- Удалено ~380 строк мёртвого кода геометрического матчинга
## FamilyManager
### 🔄 Единый движок актуализации базы (ADR-054)
Стадийные диалоги миграций заменены одним движком:
- Реестр задач `IDatabaseActualizationTask`: детект по пустоте колонок, идемпотентное применение, маркеры ошибок
- Каждый ожидающий файл семейства открывается **ровно один раз** — снапшот и геометрия извлекаются в одной сессии
- Три задачи на старте: `hash-v2` (критическая), `attributes-v1` и `glb-v1` (опциональные — чинят повреждения #151/#152/#153 без переимпорта)
- Критические ожидания блокируют базу на запись до полного обновления; тексты гейта/баннера содержат требуемую версию Revit
- Опциональные ожидания — единая янтарная точка; точка краснеет при любом критическом гейте
- Один modeless-диалог прогресса, одна сводка с очисткой
### 🧩 Подсистема фактов о семействах (ADR-055)
- Факты извлекаются из файла семейства по реестру правил и показываются в заголовке свойств рядом с «Revit Category»
- Первый факт — **Part Type («Тип детали»)** для четырёх категорий фитингов (Pipe/Duct/CableTray/Conduit Fitting) с официальной RU-локализацией Autodesk: «Мультипорт», «Соединение», «Механическое сочленение» и т.д.
- Хранение в БД (схема V22): `family_facts` с сентинелами для «вычислено, но отсутствует»; факты **не входят** в контент-хэш
- Задача актуализации `family-facts-v1` дозаполняет старые базы; новое правило в реестре автоматически расширяет детект
### 🗂️ Revit-категория в свойствах + задача revit-category-v1
- Поле «Revit Category» (read-only) в окне свойств для загружаемых **и** системных семейств
- Все пути записи (UC-1…UC-4) заполняют категорию; UPDATE-пути дозаполняют через `COALESCE` — существующие значения не затираются
- Опциональная задача `revit-category-v1` дозаполняет старые базы (колонка из V11 не была заполнена)
### #️⃣ Контент-хэш v3 — FHV3 (#159)
- Категория стала **локаль-инвариантным ординалом** — RU и EN Revit дают одинаковый хэш одного и того же семейства
- Новые канонические секции: FACTS (Part Type), FLAGS (Shared/WorkPlaneBased/AlwaysVertical/CutWithVoids), CONN (домен/форма/размеры коннекторов, SystemClassification, Origin с точностью 1e-4 ft, топология связей), STRUCT (составные слои стен/перекрытий/кровель/потолков), ROUTING (правила маршрутизации + PreferredJunctionType)
- Геометрия дополнена BoundingBox/SurfaceArea/длинами 2D-кривых; non-shared вложенные семейства входят в NESTED
- Критическая задача `hash-v3` заменяет `hash-v2`: детект покрывает v1/v2/NULL, системные группы пересчитываются полностью из staged .rvt
### 🔒 Индикация недоступных семейств в дереве каталога
- Значок замка слева от имени, серый текст семейства/типов, тултип с причиной и способом исправления
- Два состояния: **Deprecated** (восстановить через Свойства → Статус) и **RevitVersion** (активная версия сохранена в более новом Revit; тултип подскажет, есть ли совместимая версия в каталоге)
- Команды LoadToProject / PlaceType / drag-размещение блокируют Revit-несовместимые семейства в соответствии с визуальным состоянием
- Исправлен резолвер версий (legacy-баг ABS): больше не выбирается файл НОВЕЕ текущего Revit — берётся старшая версия ≤ целевой
### 📥 Импорт атрибутов из файла общих параметров (ФОП)
- Кнопка «From SP file» в библиотеке атрибутов: парсер ФОП на чистом C# (секции *GROUP/*PARAM, BOM-детект), диалог выбора с поиском и фильтром по ФОП-группе, уже существующие атрибуты недоступны
- Выбранные параметры добавляются как несохранённые черновики (фиксация через OK); путь к ФОП кэшируется в user-settings.json
- Автодополнение групп атрибутов: редактируемый ComboBox с contains-фильтром, одиночный клик для редактирования колонки Group
### 🏷️ Теги: редактор и поиск
- Исправлен ввод тегов: запятая определяется по текстовому вводу, а не физической клавише — RU-раскладка («б» на той же клавише) больше не «съедается»
- Чипы тегов переносятся по строкам (WrapPanel) и не сдвигают layout при появлении
- **Быстрый поиск по имени ИЛИ тегу**: токены через И, внутри токена — ИЛИ; семейства, найденные только по тегу, показывают до 3 совпавших чипов с подсветкой причины совпадения
### 🛠️ Batch-импорт и мелкие UX-улучшения
- Тултип с именами типов в колонке Types batch-импорта (источник тот же, что у счётчика — тултип всегда совпадает с числом)
- Единое правило отображения безымянного типа `FamilyTypeSnapshot.ResolveDisplayName` — сырое `<default>` больше не видно на вкладке Versions
- Фильтр групп в CategoryTreeEditor всегда виден при выбранной категории (убран двойной рендеринг «No groups»)
### 🗄️ Управление базами
- **Удаление/отключение последней базы разрешено** — исторический запрет устарел; при пустом списке показывается placeholder-подсказка с кнопкой «+» и водяной знак «No databases» в ComboBox подключений
- **Read-only SQLite для роли Engineer** на общих SMB-каталогах: подключения открываются с `Mode=ReadOnly` — инженер не создаёт journal-файлы и не пишет в таблицы (защита в глубину поверх RBAC-гейтов UI, меньше блокировок на сетевом ресурсе)

## 🔧 Улучшения
### Логирование и производительность логов
- **Лог-спам устранён: 74 МБ → 1 МБ за сессию** — аудит сессии на 374k строк показал, что 98.5% строк были START/END-маркерами одного BeginScope внутри CSV-парсера, вызываемого ~184k раз; scope-маркеры игнорировали MinLevel. Маркеры теперь пишутся только на Debug-уровне, BeginScope убран из горячих циклов, двойной парсинг ячеек объединён в один проход
- **Ротация лога внутри сессии** — раньше ротация выполнялась только между командами, и одна сессия росла бесконечно; теперь по размеру каждые 1000 записей
- Команды, возвращавшие `Result.Failed` молча (About/Settings/FamilyManager), теперь пишут Error с типом исключения и стеком
- Все Warn-сообщения дополнены actionable-подсказками `[Action: ...]` (конвенция L9)
- `record with` в STA-циклах заменён на LINQ Select, материализованный до мутации
### Стабильность и ресурсы
- **Утечки памяти через статические события** — AboutViewModel, FieldLibraryViewModel, AttributeLibraryViewModel теперь отписываются от статических/singleton-событий на всех путях закрытия (X, Alt+F4, кнопки); ранее каждое открытие диалога «О программе» рутировало VM на всю сессию Revit
- **Латентный дедлок устранён** — `GetAwaiter().GetResult()` на главном потоке Revit в drop-handler и Stale Update ExternalEvent работал только благодаря синхронному завершению SQLite-вызовов; вложенные имена теперь резолвятся ДО блокирующей секции (AsyncBridge для чистого SQLite)
- **I-03: TransactionGroup через ITransactionService** — прямые `new TransactionGroup` заменены на `BeginGroupSession`; assimilate только при реально закоммиченной перезагрузке, при исключении весь пакет откатывается
- **COM-cleanup (REVIT-237190)** — `Marshal.ReleaseComObject` после `Close(false)` для документов, открытых через `OpenDocumentFile`
- **SwitchToPath атомарен** — создание директории и проверка journal-mode внутри lock; конкурентное переключение больше не может «перепутать» базы
- **Dispatcher-маршаллинг** — batch-переименование использует инжектированный IDispatcher вместо `Application.Current?.Dispatcher` (null в net48)
- Сравнения путей файлов — OrdinalIgnoreCase; тихие catch'и в импорте/переключении баз логируются
### Инфраструктура зависимостей
- Microsoft.Data.Sqlite 8.0.28 → 8.0.29
- Dependabot: заморожены runtime-критичные зависимости, ломающие сборку/загрузку (CommunityToolkit 8.4.2 на net48, DI.Abstractions 10.x, SQLitePCLRaw 2.1.12 с удалённым win-arm, пины полифиллов из ADR-042)

### PipeConnect
- **Отвод с шаблоном 45° на 90° терял список DN** (#161) — геометрический матчинг коннекторов давал score 0.7071 < 0.99 и молча отключал lookup-таблицу; заменён на прямую привязку через MEPFamilyConnectorInfo
- **CTC мог записаться не в тот коннектор** (#161) — origin-based матчинг расходился при instance-параметрах, отличных от шаблона; заменён каскадом IsPrimary + порядок индексов
- **Клапаны ложились вверх ногами при сбросе вращения, отводы не вращались** (#160) — замер по BasisY трансформа семейства вырождался; теперь через BasisY свободного коннектора
- **Тройник «прыгал» на отводной порт** (#163) — корневой динамик восстанавливался из дефолта сессии, игнорируя выбор цикла коннекторов
- **«Блокировать» не работал для труб** (#165) — Init-выравнивание поглощало смещение в длину трубы и auto-seal пересоединял сеть до того, как пользователь успевал тронуть toggle; «+» и «Connect all» оставались недоступны
- **Повторные выравнивания ломали редуктор** (#167) — при dynCtc=0 Strategy 1 переворачивал редуктор обратно, записывая нисходящую комбинацию DN и ломая семейство; lookup'ы правил теряли виртуальный CTC («rule 0<->0»); Connect() не откатывал transaction group при ошибке («transaction was opened but not closed»); CTC-flush перенесён ДО валидации (LoadFamily может сбросить instance DN)
- **ConnectAll цепи из 50 элементов «вешал» Revit на минуты** — тяжёлая перезагрузка размеров на каждом элементе; теперь один раз в конце обхода
- **Петли сети оставались отсоединёнными после полного ресайза** — каскад давал концам петли разные DN; восстановление теперь покрывает редуктор + поглощение
- **Инфо-баннер «прыгал» между кликами +/−** — фиксированная двухстрочная высота
- Кнопки сброса/смены подключения — равной ширины в центрированной сетке 360px; убран лишний индикатор статуса из нижней панели
### Критические
- **Падение Revit (net48) / молчаливое неоткрытие диалога (net8) при подтверждении удаления** (#154) — ConfirmationDialogView.xaml содержал два дочерних элемента в неявном `<Window.Resources>` (SingletonResources + конвертер), что давало `XamlDuplicateMemberException` при LoadBaml. Затронуты все вызовы ShowConfirmation: удаление семьи, MakeActive на вкладке Versions, гейт обновления базы. Исправлено каноническим паттерном MergedDictionaries; аудит XAML — это было единственное нарушение в решении
- **ProjectManagement: потеря несохранённых изменений при Share** (#150) — non-workshared .rvt закрывался через `Close(false)` без `Save()`; изменения пользователя молча терялись. Теперь `Save()` выполняется до закрытия, при ошибке share прерывается ДО закрытия чего-либо
- **FamilyManager: ручной выбор общей базы затирался при активации документа** (#148) — ProjectBaseActivator безусловно откатывался к ПЕРВОЙ общей базе, если ни одна проектная не совпала с активным документом. Теперь ручной выбор сохраняется; откат — только когда ничего не активно или активная база перестала совпадать
- **FamilyManager: диалог режима загрузки shared nested молча пропускался** (#147, #149) — случайно удалённая регистрация `WpfDialogPresenter` для SharedFamiliesLoadModeDialogViewModel приводила к тихому fallback на Skip. Регистрация восстановлена; прогресс конфликтов теперь честно показывает порядковый номер конфликта, а не «1 из N всех вложенных»
### Актуализация и данные
- **«Вечная янтарная точка» для 2D/annotation-only семейств** (#157) — семейства без извлекаемой 3D-геометрии никогда не могли удовлетворить детект glb-v1, точка горела бесконечно. Схема V23: `glb_state = -1` (терминальный маркер «нет геометрии»); повторный импорт с реальной геометрией лечит маркер обратно; сбои записи GLB остаются без маркера (ретраятся)
- **Команда «Обновить базу» была доступна read-only ролям** — Engineer подключается в Mode=ReadOnly, движок открывал файлы впустую и фейлил каждую запись, гейт не снимался никогда. Теперь команда/баннер требуют CanEdit (Owner/BimMaster), тексты объясняют, кто может выполнить обновление; защита в глубину в DatabaseUpdateStateService
### Извлечение атрибутов (#151, #152, #153)
- **Единицы измерения атрибутов** — Double-значения форматируются по единицам документа-владельца через `UnitFormatUtils.Format` (R21+) / legacy DisplayUnitType (R19–R20); исправлена RU-локализация Autodesk «бары» → «бар» (ГОСТ 8.417)
- **Безымянный дефолтный тип** — извлекается как хэш-стабильная константа `<default>` только когда именованных типов нет (чинит полную потерю атрибутов у бестиповых семейств)
- **Revit 2023 READERROR** — резолв спецификации параметра через кэшированную рефлексию на R21 (`GetSpecTypeId` удалён в 2023, `GetDataType` добавлен в 2022)
### UI
- **ComboBox фильтра групп** — всегда виден при выбранной категории; убран курсивный лейбл «No groups», рендеривший одно логическое состояние двумя способами (#158)
- **BoolToVis в CategoryTreeEditor** указывал на стоковый WPF-конвертер, молча игнорирующий `ConverterParameter=Invert` — заменён на SmartCon.UI BoolToVisibilityConverter
- Properties: скрыт селектор типа для единственного дефолтного/виртуального типа, статус-пилюля заменена иконкой с тултипом, колонка имён атрибутов автоматизирована через SharedSizeGroup

## 🧪 Как тестировать beta
### PipeConnect: элемент-wise цепь и LockNetwork
1. Постройте цепь кнопками +/− — каждый присоединённый элемент становится активным (панель показывает его); вращайте активный элемент вокруг родительского коннектора шагом 45°
2. Включите «Блокировать» и запустите «Подключить всё» — сеть двигается одним жёстким телом, без компенсаций
3. Для трубы-динамика переключите «Блокировать» туда-обратно (#165): ON — поглощение откатывается, сеть отсоединена; OFF — поглощение возвращается, seal повторяется
4. После жёсткого Connect вращайте — вся герметизированная сеть крутится вокруг граничного коннектора; петли сети восстановлены
5. С несовпадением DN на границе — редуктор из маппинга или диалог с зазором 100 мм
### PipeConnect: навигация и стабильность
1. Кнопки [-] [Просмотр] [+] в нижней панели: «Просмотр» центрируется на активном коннекторе, точка не уезжает за диалог при повторных зумах (#166)
2. Отвод с шаблоном 45° поставьте на 90° — список DN из lookup-таблицы полный (#161); проверьте запись CTC на фитингах Kan-therm
3. Цикл коннекторов на тройнике: выберите боковой порт циклом, нажмите Connect — соединение идёт именно по выбранному порту (#163)
4. Кнопка сброса вращения: клапан не ложится вверх ногами, отвод поворачивается (#160)
5. ConnectAll на сети из ~50 элементов — без многоминутного «зависания»
### Движок актуализации (ADR-054)
1. Подключите старую базу (или повредите тестовую через `tools/damage-catalog-db.ps1`) — в меню должна появиться точка ожидания; счётчик должен совпасть с выводом скрипта
2. Нажмите «Обновить базу» — один диалог прогресса, одна сводка; после завершения точка гаснет
3. Проверьте под ролью Engineer: команда недоступна, баннер/гейт сообщают, что обновление может выполнить Owner или BIM-мастер
4. Семейство только с 2D (без 3D) — после обновления янтарная точка НЕ должна гореть вечно (#157)
### Факты и категории (ADR-055)
1. Откройте свойства фитинга (отвод/тройник) — в заголовке видны «Revit Category» и «Тип детали» на русском
2. Откройте свойства системного семейства (труба/стена) — Revit-категория показана
3. Импортируйте семейство повторно — факты должны обновиться (self-heal), а не задвоиться
### Недоступные семейства
1. Найдите семейство, сохранённое в более новом Revit, — в дереве замок, серый текст, тултип с причиной
2. LoadToProject / PlaceType для него заблокированы
3. Сделайте активной совместимую версию на вкладке Versions — замок исчезает сразу, даже при Cancel диалога
### Атрибуты из ФОП и теги
1. Библиотека атрибутов → «From SP file» → выберите ФОП, отметьте параметры → OK — атрибуты добавлены
2. В редакторе тегов переключитесь на RU-раскладку и введите тег с буквой «б» — чип НЕ должен коммититься раньше времени
3. Быстрый поиск по слову из тега — семейство найдено, чип совпавшего тега виден в строке дерева
### Стабильность (регрессии)
1. Удаление семьи / MakeActive / гейт обновления — диалоги подтверждения открываются в R25 и не роняют Revit в R21 (#154)
2. ProjectManagement: внесите изменения в .rvt БЕЗ сохранения, запустите Share — изменения должны попасть в shared-копию (#150)
3. Несколько общих баз: выберите вторую вручную, переключите документ — выбор сохраняется (#148)
4. Перетащите семейство из каталога в проект (drop) и дождитесь Stale Update — дедлоков быть не должно
5. Проверьте размер `smartcon.log` после длинной сессии — должен остаться в пределах единиц МБ, а не десятков
### Общее
1. Пришлите `smartcon.log` после теста (путь: `%APPDATA%\AGK\SmartCon\smartcon.log`)
