> **Что нового с версии 2.0.0-beta.2** — завершение **Phase 27 (Temp Removal v2)** для FamilyManager: уход от промежуточного `_stage/`, очистка мёртвого кода, bake-in Type Catalog, а также серия критических исправлений импорта активного проекта/выделенных элементов (UC-3/UC-4). Подготовлено **33 коммитами** за 5 дней (21 — 25 июня 2026).
---
## 🔥 Главное в этой версии
Этот релиз — **финальная зачистка архитектуры FamilyManager перед стабильной 2.0.0**. Сфокусирован на устранении долгих задержек, двойных записей, потерянных типов и тихих отказов импорта.
Самое заметное:
- **Импорт активного проекта и выделенных элементов (UC-3/UC-4) теперь работает стабильно** — ранее 0 семейств могли «импортироваться» без ошибок в UI: проблемы с `Collection was modified` в `stage*FromMetadataAsync`, потерянный `Source` в `FamilyBatchImportItem` и `null` managed path устраняют три класса тихих отказов.
- **Отсутствуют «осиротевшие» `_stage/` папки и `.types.json` sidecars** — loadable семейства сразу пишутся в managed storage, временные файлы удалены полностью. На старте один раз срабатывает `CleanupLegacyStageFolder` для очистки наследия прошлых версий.
- **Batch-диалог теперь открывается за <1 сек** для 50+ семейств: метаданные готовятся заранее (virtual metadata), реальная стадия запускается только после подтверждения пользователя. Переименование строки обновляет статус «Новая/Существующая» в реальном времени.
- **Multi-version build resilience**: SmartCon теперь корректно собирается на всех Revit (R19/R21/R23/R24/R25) — `AdWindows.dll` подключается условно через `<Choose>/<When>`, конструктор `ElementId` разведён по версиям.
- **Type Catalog bake-in**: реальная персистенция типов внутри `.rfa` вместо синхронизации `.txt` sidecars. Юниты `##TYPE##UNITS` корректно парсятся и конвертируются во внутренние юниты Revit (больше никаких 215-футовых вентиляторов из мм).
- **Shared-nested диалог восстановлен в Revit 2023/2024** через резолвер имён из локального каталога (workaround для официального бага Autodesk REVIT-198137).
- **net48 UI-freeze workaround**: «nudge» через AdWindows InfoCenter balloon после OpenDocumentFile+Close восстанавливает WPF render thread (REVIT-236376/237190).

## ✨ Features
### 🟠 Type Catalog bake-in в managed .rfa (`8ffe965`, `489a7f3`, `19e220e`, `60dd77f`)
Замена симуляции Type Catalog на **прямой bake-in**: при импорте открывается исходный `.rfa` один раз, типы из `.txt` переносятся в топологический порядок, формулы восстанавливаются, `SaveAs` пишет результат в managed storage.
- `IFamilyTypeCatalogBaker` + `RevitFamilyTypeCatalogBaker` — ключевые компоненты.
- `FamilyTypeCatalogBakingResult` — структурированный результат с `BakeStats.Converted/Failed`.
- Парсер заголовка `parameter##TYPE##UNITS` сохраняет обе аннотации: `TypeCatalogColumn(Name, TypeAnnotation?, UnitAnnotation?)`. Юниты (`millimeters`, `centimeters`, `square_*`, `watts`, `volts`, ...) конвертируются через `UnitUtils.ConvertToInternalUnits` с валидацией `UnitUtils.IsValidUnit` против спецификации параметра.
- `TypeCatalogUnitAlias` — чистый C# маппинг ~30 алиасов + singular/plural/typo-нормализация, теперь полностью юнит-тестируемая (53 параметризованных случая в `TypeCatalogUnitAliasTests`).
- StorageTypeCode выровнен с Revit `StorageType` (Integer=1, Double=2, String=3, ElementId=4) — устранены 168 `InvalidCastException` + 92 `InvalidFormat` warning'а в Revit 2023.
- `SaveTypesForRunAsync` теперь возвращает реальный `id` через `RETURNING id` (SQLite 3.35+) — устранён desync между `family_types.id` и `extracted_attribute_values.type_id`.
- IFailuresPreprocessor с полным Tammik-паттерном (`SetClearAfterRollback` + `SetForcedModalHandling(false)` + `ProceedWithRollBack`) подавляет ошибки формул в simulation-транзакции без краша Revit.
- Сокращение лога: с 172 КБ до 58 КБ на 3-семейный импорт (убран per-param Debug на hot loop, C7 rule).
- Phase 1→2→3→4 рефакторинг симуляции: один `Regenerate()` вместо N (~9 сек → ~3-5 сек на 11 типах).
- `CurrentType = tempType` перед каждым батчем `Set` (Tammik rule) — иначе все Set'ы записываются в ПОСЛЕДНИЙ тип.
### 🟠 FamilyManager: виртуальные метаданные для UC-3/UC-4 + hotfix переименования (`ffee8f3`)
Перенос стадии «создания managed файла» **из до диалога → после подтверждения пользователя**.
- Новый `FamilyImportSource` (record-union в `SmartCon.Core.Models.FamilyManager`) — несёт либо `SystemSource(categoryId, types)`, либо `LoadableSource(familyName, uniqueId, categoryName)`. Хранится в Core без зависимости от `Autodesk.Revit.DB` (I-09).
- `FamilyBatchImportItem.Source` — для UC-1/UC-2 остаётся `null` (файл уже на диске); для UC-3/UC-4 заполняется placeholder `FilePath` ("system://..." или "loadable://...") + populated `Source`.
- `BuildActiveProjectBatchItemsCoreAsync` / `BuildSelectedElementsBatchItemsCoreAsync` теперь **metadata-only**: не вызывают `CreateCleanProjectWithTypesAndInstances` / `StageLoadableFamilyFromProject`. Диалог открывается за <1 сек для 50+ семейств.
- `ProcessProjectImportAsync` запускает `StageSystemFamiliesFromMetadataAsync` / `StageLoadableFamiliesFromMetadataAsync` через `IFamilyManagerAwaitableEvent` — managed путь вычисляется up-front, Revit-API стадия выполняется на UI-потоке.
- Переименование строки в batch-диалоге теперь обновляет `Status` (New ↔ Existing) через debounced 250 ms lookup в `IFamilyCatalogProvider`.
### 🟠 FamilyManager: precomputer abstraction (`bd768f0`, fixes #82, #83)
Выделение канонического `(CatalogItemId, VersionLabel, ManagedPath)` triple в отдельный сервис.
- `IFamilyImportPrecomputer` + `LocalFamilyImportPrecomputer` в `SmartCon.Core` — single-method контракт `BuildPrecomputedTripleAsync`.
- `PrecomputedImportTriple` (immutable record) — единственная форма данных, удовлетворяющая инварианту `family_files.relative_path = '{dbRoot}/files/<id>/<version>/<name>'`.
- `FamilyBatchImportRow` поля `PrecomputedCatalogItemId/VersionLabel/ManagedPath` стали `[ObservableProperty]`-writable — rename handler может пересвязать их через тот же precomputer.
- **Fix #82**: `OnRowNameChanged` теперь корректно пересчитывает triple, не роняя `INSERT catalog_items(id=staleGuid)` с UNIQUE constraint.
- **Fix #83**: precomputer восстановлен в pure-compute (без `EnsureFamilyDirectories`) — больше нет пустых папок `v3/` рядом с `v1/` и `v2/` при отмене диалога или ошибке импорта.
- `SafeFileName.SanitizeFileName` перенесён в `SmartCon.Core` — три одинаковые private копии удалены.
### 🟠 Shared-nested family names persistence (`38f4b58`, fixes #76, #77)
Решение официального бага Autodesk **REVIT-198137**: в `IFamilyLoadOptions.OnSharedFamilyFound` параметр `sharedFamily` возвращается `null` (или указывает на parent) в Revit 2023 / 2024 < 24.3.0.13.
- Новая SQLite таблица `family_nested_shared_families` (миграция V13) сохраняет список имён общих вложенных семейств **на момент импорта**, в одном `OpenDocumentFile` цикле (V3 инвариант: один OpenDocumentFile на .rfa).
- `SharedFamilyNameResolver` (чистый C#, юнит-тестируемый) — fallback chain `RevitApi → CatalogDb → FallbackPlaceholder`. Thread-safe через `Interlocked.Increment`.
- В `SharedFamiliesLoadModeDialog` добавлены `BatchProgress` ("Shared nested 2 of 5") и `SourceIndicator` ("name from SmartCon catalog" / "name unavailable").
- Подробный debug-лог `Resolve[#N]: RevitApi path` / `CatalogDb fallback — REVIT-198137 TRIGGERED` для трассировки после manual-теста.
- Тестовое покрытие: `SharedFamilyNameResolverTests` (11), `LocalSharedNestedFamilyRepositoryTests` (18), `SharedFamiliesLoadModeDialogViewModelTests` (+6), `LocalCatalogMigratorTests` (+1), `FamilyExtractionResultTests` (+5).
- **Breaking change v2.0.0**: для каталогов из < 2.0.0 shared-nested семейства показывают placeholder до повторного импорта в Family Manager (Warn в логе подсказывает действие).

## 🔧 Bug Fixes
### FamilyManager
- **#85 `bd8b0b7`** — **sync types on active family import**: устранены «ghost types» (удалённые типы в Revit оставались в `family_types` после повторного импорта активного файла — UPSERT без DELETE). Решение через `IFamilyTypeRepository.SaveTypesAsync` + `SaveTypesForRunAsync` с явным DELETE+INSERT в одной транзакции, FK CASCADE V15-миграция для `extracted_attribute_values`, явный `_dispatcher.InvokeAsync` после save. Закрыт `M-019-003`.
- **#84 `5387455`** — **re-sync FamilyVersion marker on Import Active File / Selected Elements**: после `ProcessProjectImportAsync` SmartCon_FamilyVersion_v1 ES marker отсутствовал на импортированных семействах, и следующий «Проверить» помечал их stale с `NoEntityStorage`. Новый pure-Core helper `LoadableMarkerLogic` пишет маркер сразу после catalog write. System families (.rvt-containers) намеренно не трогаются (ADR-030 Out of Scope).
- **#79 `47fd365`** — **hotfix close RFA after import + Access Denied**: `CloseFamilyDocumentAsync` после успешного импорта активного `.rfa` корректно закрывает документ и возвращает фокус на хост-проект. Удалена `.txt` sidecar cleanup в `LocalFamilyImportService.CleanupFileAsync` (ADR-033 bake-in). `PrepareManagedRfaAsync` short-circuit когда source уже в managed — self-copy пропускается. Регресс-тест `ImportActiveFile_UserCancelsBatchDialog_DoesNotCloseActiveFamilyDocument`.
- **`6828a68`** — **write loadable staging directly to managed storage, kill `_stage/`**: `StageLoadableFamilyFromProject` теперь требует `managedRfaPath`, fallback на `dbRoot/files/_stage/{guid}/{name}.rfa` удалён. `PrepareManagedRfaAsync` получил второй early-out (source уже под `{dbRoot}/files/` → skip copy). `App.OnStartup` запускает одноразовый `CleanupLegacyStageFolder`.
- **`3b4d795`** — **disable row virtualization in batch import dialog**: `DataGrid.EnableRowVirtualization=false` для batch-диалога — TwoWay binding `DataGridRow.IsSelected` стабилен, мульти-выбор не «залипает» при скролле. Dataset ограничен ≤100 семейств, virtualization тут не даёт преимущества.
- **`d4f9d15`** — **`stage*FromMetadataAsync` must not mutate List during foreach**: классическая ошибка `Collection was modified; enumeration operation may not execute` при `items[i] = item with { ... }` внутри `foreach`. Заменено на index-based for-loop + side dictionary. Задокументирована inline для будущих maintainers.
- **`aa859e8`** — **preserve `FamilyBatchImportItem.Source` across batch dialog**: `GetResultItems()` ре-эмитил только первые 11 ctor параметров и ронял `Source` (default `null`). Без Source `StageSystem/LoadableFamiliesFromMetadataAsync` пропускали все строки — импорт молча давал 0. Добавлены регресс-тесты `GetResultItems_PreservesSource_On{Loadable,System}Row` и глубокое диагностическое логирование (BeginScope + per-item Warn на file-not-found + try/catch).
- **`fef0197`** — **ShowBalloonTip workaround for REVIT-237190 family-upgrade UI freeze**: после каждого `OpenDocumentFile + Close` показывается near-invisible InfoCenter balloon через `AdWindows.dll` — собственный Win32 window форсирует focus event, ре-синхронизирующий WPF render thread с UI thread (REVIT-236376 / REVIT-237190, R2023 net48 / Windows 11).
- **`7ccaf3c`** — **keep category DisplayName when importing active project with loadable families (#75)**: project-name fallback для single system category теперь применяется только когда нет loadable семейств. В смешанных проектах system семейства больше не называются по имени `.rvt` файла.
- **`19e220e`** — **parse `##TYPE##UNITS` in Type Catalog header and convert to Revit internal units**: 215 мм превращалось в 215 футов. `RevitUnitsCompat.CatalogCellToInternalUnits` валидирует unit против `SpecTypeId.Length`, конвертирует через `UnitUtils.ConvertToInternalUnits`. R21+ использует `FamilyParameter.GetUnitTypeId()` + `SpecTypeId`, R19-R20 — `param.DisplayUnitType` + category heuristic.
- **`37cacf5`** — **break `FamilyBatchImportItem` dependency on RevitAPI + retire Task.Run**: `SelectedSystemType` (с `BuiltInCategory`) вынесен в Core `FamilySourceTypeInfo` (CategoryId = plain int) — маппинг на boundary FamilyManager. Удалён бесполезный `Task.Run` вокруг уже-async метода (50% flaky test). Off-by-one в `ImportFile_SourceEqualsManagedPath_SkipsCopyAndSucceeds` исправлен.
- **`cb23f8b`** — **post-audit cleanup** — dead code removal (`StageSystemFromAnalysis` — 45 строк, не вызывается с v2.0.0; `Extract(string,...)` / `Extract(Document,...)` overloads — ~95 строк), I-03 violation fix в `NormalizeInstanceDimensions` (теперь instance method → `RunInTransaction` + `SmartConFailurePreprocessor`), dispatcher marshalling по ADR-031, убран long-lived `BeginScope` (C15 — 2 МБ спама на 100-файл импорт), `System.Diagnostics.Stopwatch` → `SmartConLogger.Measure`, 15+ `Warn(...)` дополнены `[Action: ...]`.

- **Shared-nested family names**: для каталогов из < 2.0.0 имена общих вложенных семейств показывают placeholder до повторного импорта в Family Manager. `Warn` в логе подсказывает действие. Полная совместимость возвращается после одного re-import через FM.
