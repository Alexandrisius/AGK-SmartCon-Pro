### 🚀 Новое: Полный импорт параметров семейства
**FamilyManager** теперь извлекает из `.rfa` **все общие и системные параметры**, а не только те, что привязаны к текущей категории.
**Что изменилось:**
- При импорте данных извлекаются абсолютно все параметры семейства
- Параметры хранятся в БД даже если они не привязаны к категории (`attribute_id = null`)
- При смене категории семейства во вкладке **Атрибуты** автоматически отображаются параметры, привязанные к новой категории — без повторного импорта
- Значения параметров сопоставляются по `ParameterName` как fallback, если `AttributeId` отсутствует
**Технические детали:**
- SQLite schema v8: `extracted_attribute_values.attribute_id` → `nullable TEXT`
- Убран `FOREIGN KEY` на `attribute_definitions` (данные больше не теряются при удалении определения)
- `UNIQUE` constraint изменён на `(catalog_item_id, version_id, type_id, parameter_name)`

### 🐛 Исправления FamilyManager
| Проблема | Исправление |
|----------|-------------|
| Фриз dockable панели после импорта данных | Убрано блокирующее логирование (`SmartConLogger.Freeze`) из `ExternalEvent` callback |
| Deadlock при async импорте | `TaskCompletionSource` с `RunContinuationsAsynchronously` — continuation выполняется в thread pool, не на Revit UI thread |
| Падение при отсутствии подключения к БД | Graceful degradation, корректные сообщения об ошибках |
| Краш диалога профиля | Исправлен null reference при открытии профиля |
| Пустая строка статуса | Локализация статусных сообщений восстановлена |
| Проблемы с рендерингом дерева | Исправлены артефакты отображения категорий |
| Удаление семейства | Исправлена ошибка при удалении семейства из каталога |
| Авто-сохранение типов при Load/Place | Убрано неявное сохранение типов (типы теперь управляются явно) |
