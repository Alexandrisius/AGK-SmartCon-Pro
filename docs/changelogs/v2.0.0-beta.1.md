# SmartCon 2.0.0-beta.1
> **Что нового с версии 1.9.3** — крупное обновление модуля **FamilyManager** (управление каталогом семейств Revit). Подготовлено **59 коммитами** за 10 дней (29 мая — 8 июня 2026).
---
## 🔥 Главное в этой версии
FamilyManager — модуль, в котором вы собираете, храните и обновляете библиотеку `.rfa`-семейств для проектов — прошёл через несколько фундаментальных переработок. Внешне это выглядит как «новые кнопки, новые диалоги и новые статусы», внутри — полностью пересобранный конвейер импорта, новый формат базы и подготовка к работе с типоразмерами.
Самое заметное для вас:
- появился **пакетный импорт** с режимами «Новая версия / Перезаписать / Пропустить»;
- в дереве каталога теперь видно, какие семейства **устарели** относительно загруженных в проект;
- семейства можно **перетаскивать** в проект прямо из панели FM;
- можно импортировать **системные семейства** (трубы, воздуховоды, стены, гибкие трубы, лотки, короба) из активного проекта;
- добавлен **тип-ориентированный режим** работы с Type Catalog (`.txt`).

## ✨ Новые возможности
### 📦 Пакетный импорт семейств (Batch Import v4)
Теперь можно выбрать сразу **несколько `.rfa`-файлов** и загрузить их в каталог за один проход.
- В диалоге пакетного импорта отображается таблица: имя файла, версия Revit, размер, статус, выбранное действие.
- **Статусы** для каждого файла:
  - `Новое` — такого семейства в каталоге ещё нет.
  - `Существующее` — семейство с таким именем уже есть, файл отличается по содержимому.
  - `Дубликат` — файл с таким же SHA256 уже есть в каталоге (автоматически помечается «Пропустить»).
- **Действия** (выбирается вручную для каждой строки):
  - **Новая версия** — создаётся следующая версия (`v2`, `v3` и т.д.), текущая версия в каталоге переключается на новую.
  - **Перезаписать текущую** — содержимое файла заменяется, но номер версии остаётся прежним.
  - **Пропустить** — файл не импортируется.
- Перед открытием диалога пакетного импорта права доступа проверяются (RBAC) — если у вашей роли нет прав на импорт, диалог не откроется.
- Реализован полный аудит импорта: ошибки извлечения типов и атрибутов отображаются в статус-баре.
### 🟠 Индикатор устаревших семейств (Stale Marker)
В дереве каталога теперь видно, какие семейства в вашем проекте имеют **более старую версию**, чем та, что лежит в каталоге.
- При каждой загрузке семейства в проект плагин запоминает, **какая именно версия** была загружена.
- При обновлении дерева каталога (Refresh) для каждого семейства сравнивается:
  - версия, загруженная в проект (`loaded_version_label`);
  - текущая версия в каталоге (`current_version_label`).
- Если они различаются — в дереве рядом с названием семейства появляется **оранжевый маркер** и подпись `[Устарело]`.
- Это работает **батчем** (один SQL-запрос для всего дерева), не тормозит UI даже на больших каталогах.
- Дополнительно в семействе теперь отображается **имя текущей версии** (например, `v3`).
### 🖱️ Drag & Drop в проект
- Любое семейство из дерева каталога можно **перетащить** прямо в окно Revit — оно автоматически разместится там, где вы отпустите кнопку мыши.
- При перетаскивании на **раскрытую категорию** (а не на конкретное семейство) — семейство кладётся в эту категорию.
- В статус-баре отображается результат: успешное размещение, имя вложенного семейства, ошибка (если что-то пошло не так).
- Фокус окна Revit корректно возвращается после размещения — больше не нужно кликать в Revit вручную.
- Кэш файлов семейств оптимизирован: повторные перетаскивания работают быстрее.
### ✏️ Открытие семейства в Family Editor
- Добавлена кнопка **«Редактировать»** в контекстном меню семейства — открывает выбранное `.rfa` в Family Editor Revit, не покидая SmartCon.
- Добавлена кнопка **«Загрузить активное семейство»** — если в Revit сейчас открыт `.rfa`-файл, его можно сразу импортировать в каталог.
- Исправлен импорт семейств, открытых в Family Editor (раньше терялись привязанные `.txt` Type Catalog).
### 🔍 Поиск выделенного в каталоге
- В панели инструментов добавлена кнопка **«Найти в каталоге»**.
- Если в дереве Revit выделено какое-то семейство, кнопка подсвечивает его в каталоге FM и прокручивает дерево к нужной категории.
- Положение прокрутки и выделение сохраняются — удобно сверяться с тем, что уже используется в модели.
### 🏗️ Поддержка системных семейств
Появился полноценный импорт **системных семейств** — тех, что встроены в Revit и не хранятся в отдельных `.rfa`:
- **Трубы** (`OST_PipeCurves`)
- **Гибкие трубы** (`OST_FlexPipeCurves`) — добавлено в этом релизе
- **Воздуховоды** (`OST_DuctCurves`)
- **Гибкие воздуховоды** (`OST_FlexDuctCurves`)
- **Короба** (`OST_Conduit`)
- **Лотки** (`OST_CableTray`)
- **Стены** (`OST_Walls`)
Каждая категория имеет **свой обработчик размещения** (placement handler) — атрибуты корректно извлекаются через `Pipe.Create`, `Duct.Create`, `Wall.Create` и др.
#### Команда «Импорт выделенных элементов»
- Кнопка «Импорт системного семейства» переименована в **«Импорт выделенных элементов»** — теперь она принимает **любые** элементы (и системные, и загружаемые семейства).
- Новый фильтр выделения `AnyElementSelectionFilter` принимает как `FamilyInstance`, так и системные категории.
- Импорт работает в 5 фаз: анализ → подтверждение → подготовка → диалог пакетного импорта → диспетчеризация по источнику.
#### Команда «Импорт активного файла»
- «Импорт активного файла» теперь импортирует **и системные, и загружаемые** семейства из активного проекта.
- Сначала показывается **быстрый анализ** (без обращения к `.rfa`-файлам) — менее секунды даже на 200 семействах.
- Пользователь видит сводку: «5 системных категорий (37 типов) и 87 загружаемых семейств» — и подтверждает.
- Только после подтверждения плагин начинает открывать `.rfa` через `EditFamily + SaveAs` — никаких зависаний до клика.
- В каталог попадают **только размещённые** семейства (через `OfClass(FamilyInstance) + GroupBy(fi.Symbol.Family.UniqueId)`), а не все загруженные в проект.
### 🧬 Тип-ориентированный режим (Type-Centric Workflow)
- Для каждого семейства теперь извлекается и сохраняется **полный список типоразмеров** (Type Catalog).
- Поддерживается универсальное определение кодировки `.txt` Type Catalog — корректно работает с кириллицей, разными региональными настройками.
- Парсер соответствует **RFC 4180** (CSV) — корректно обрабатывает запятые в кавычках, экранирование, CRLF/LF.
- Исправлено слияние Type Catalog для семейств с **0 типов**, **дубликатами** и **несовпадающими типами**.
- Поддерживается **виртуальные типы** (например, динамически вычисляемые значения).
- Добавлена команда **«Перезаписать Type Catalog»** в подменю обновления семейства.
- Атрибуты извлекаются через единый сервис `IFamilyDataExtractionService` (без дублирования логики).
### 📂 Импорт активного `.rfa` без потери Type Catalog
- При импорте активного семейства (открытого в Family Editor) **`.txt` Type Catalog теперь сохраняется** — раньше файл терялся.
- Реализованы сервисы:
  - `IFamilySidecarLocator` — находит связанные `.txt` рядом с `.rfa` (13 unit-тестов).
  - `IActiveFamilyFilePreparer` — подготавливает файлы с учётом сайдкаров.
  - `IActiveDocumentClassifier` — различает проект, активное семейство и неподдерживаемые документы.
  - `IActiveImportCleanupService` — убирает временные файлы.

## 🔧 Улучшения и исправления
### Пакетный импорт и обновление
- Двойной показ диалога пакетного импорта в команде «Импорт выделенных элементов» — исправлен (теперь диалог показывается строго один раз, в `ProcessProjectImportAsync`).
- «Импорт активного файла» больше не предлагает загрузить **все** семейства проекта — только реально размещённые.
- Поиск замены общего вложенного семейства отображается в статус-баре (раньше молча подменялся файл).
- Окно Revit получает фокус обратно после размещения через Drag & Drop.
- Сообщения об успехе Drag & Drop отображаются в статус-баре.
- Кнопки-«сплиты» в панели инструментов исправлены (корректное состояние enabled/disabled).
- Отображение категории в строках пакетного импорта приведено к нормализованному виду (без дубликатов и с потерей данных).
- Контекстное меню категории очищено от неиспользуемых команд.
- Команды `Импорт папки` и `Импорт данных` удалены из UI — оставлен только пакетный импорт.
- Кнопка «Инкремент версии» переименована в **«Новая версия»** (и в русской, и в английской локали).
- Диалог пакетного импорта корректно закрывается по `Esc` через стандартный `IsCancel` (раньше был костыль с `PreviewKeyDown`).
- Путь хранения `.rfa` упрощён: убран сегмент `r{revitVersion}` для новых файлов; старые файлы читаются через fallback (обратная совместимость).
- Извлечение типов и атрибутов при пакетном импорте работает с `Marshal.ReleaseComObject` — устранена утечка COM-объектов, которая раньше приводила к memory corruption при импорте более 32 файлов подряд.
### Категории
- При удалении категории курсор автоматически переходит на **соседнюю** категорию — раньше дерево оставалось без выделения.
- **Исправлен баг #63**: импорт больше не дублирует категории и не скрывает атрибуты. Категория теперь читается и пишется **из авторитетного источника** (`category.Name` напрямую из объекта категории, а не из строки-денормализованного поля).
- В нормализации категории исправлена ошибка отступов (style).
- В конструкторе `FamilyBatchImportRow` устранено предупреждение о nullable.
### Производительность и надёжность
- SQLite: исправлена **ошибка Error 14** (отсутствующая таблица) при подключении к пустой базе реестра.
- SQLite: переход на **DELETE journal mode** (вместо WAL) — устраняет необходимость в ручном `Checkpoint`.
- Все `await` в hot-path теперь используют `ConfigureAwait(false)` — нет блокировок UI при I/O.
- Запись статистики использования переведена в `FireAndForget` (не блокирует загрузку семейств в проект).
- **Сканирование семейств** в активном проекте — теперь `O(F)` через `OfClass(FamilyInstance) + GroupBy(fi.Symbol.Family.UniqueId)` вместо полного прохода по проекту.
### Логирование
- Уровни логирования теперь зависят от **конфигурации сборки**: `Debug` — подробный, `Release` — лаконичный. Переопределяется переменной среды `SMARTCON_LOG_LEVEL`.
- Добавлены **структурированные scopes** с `OpId` (идентификатор операции) и `Measure` (время) — легко фильтровать логи по конкретному импорту.

## 🏗️ Архитектурные изменения (для разработчиков и продвинутых пользователей)
Хотя снаружи это незаметно, под капотом проведена большая рефакторинг-кампания. Цель — устранить накопленный технический долг и подготовить FM к работе с **тысячами семейств** в каталоге.
### Принятые архитектурные решения (ADR)
- **ADR-018: Рефакторинг FamilyManager** (Phases 1-7) — поэтапный переход к чистой DI-архитектуре.
- **ADR-019: Refactoring Migration Backlog** — бэклог оставшихся улучшений (мигрировано в ADR-025 после ребрэндинга).
- **ADR-021: Pre-release Versioning and Beta Release Strategy** — политика beta-релизов, SemVer 2.0.0, `IncludePrerelease`-флаг в настройках.
- **ADR-022: FamilyManager RBAC** — ролевая модель доступа (кто может импортировать, редактировать, удалять).
- **ADR-023: FamilyManager Type-Centric Workflow** — типоразмеры как first-class citizens.
- **ADR-024: Active Family Import Preparer** — импорт активного `.rfa` без потери Type Catalog.
- **ADR-025: Refactoring Migration Backlog** — обновлённый бэклог миграций (M-019-001..005).
- **ADR-027: Placed Families v2** — импорт размещённых семейств: `OfClass(FamilyInstance)` для анализа, `EditFamily` только для извлечения.
### Рефакторинг (внутренние изменения, без влияния на UI)
- **«God Object» ликвидирован.** 30-параметровый конструктор `FamilyManagerMainViewModel` заменён на агрегат `FamilyManagerServices` — все сервисы сгруппированы в один объект.
- **13 sync-over-async мест** переписаны на нормальный `async/await` через `RaiseAsyncTask` — больше никаких deadlock'ов.
- **`async void` уничтожен.** Все `FireAndForget` переведены на `Task.Run`-обёртки — без `async void` где бы то ни было.
- **`IDispatcher`** — абстракция Dispatcher, реализация `WpfDispatcher`. UI-операции больше не дёргают `Application.Current.Dispatcher` напрямую (подготовка к тестируемости).
- **`IClock`** и **`IIdGenerator`** — для подмены времени и генерации ID в тестах.
- **`SqliteConnectionExtensions`** — единый набор extension-методов для SQLite, устранено дублирование.
- **`Guard.ThrowIfNull`** — единая утилита проверки null (CA1510), заменила разнобой `if (x == null) throw` по всему коду.
- **JSON-опции централизованы** — `JsonSerializerOptions` и константы формата вынесены в одно место.
- **Package Migrator** — мигратор пакетов вынесен в отдельный сервис.
- **`LocalCatalogMigrator`** — DIP: теперь зависит от интерфейса, а не от конкретного класса.
- **Логирование через `BridgeAsyncResult`** — добавлены XML-комментарии, объясняющие почему используется `ConfigureAwait(true)`.
- **Сервисы** `FamilyManagerServices` перенесены из `ViewModels/` в `Services/` — структурное улучшение.
### Инфраструктура и зависимости
- `PolySharp` зафиксирован на версии `< 1.16.0` — устранены случайные падения сборки net48.
- `Microsoft.Data.Sqlite` обновлён в рамках совместимости (через dependabot).
- `SQLitePCLRaw.bundle_e_sqlite3` обновлён для поддержки новых сред.
- `dorny/paths-filter` обновлён в CI.
- В CI: pre-release теги (`v*-alpha*`, `v*-beta*`, `v*-rc*`) теперь запускают сборку.

## 🔄 Обновление с 1.9.3 → 2.0.0-beta.1
### Автоматическая миграция
- **Schema v9** БД применяется автоматически при первом запуске:
  - добавлена колонка `project_usage.loaded_version_label` — для работы Stale Marker.
- Старые пути `.rfa` (с сегментом `r{revitVersion}`) читаются без переноса; новые файлы пишутся по упрощённому пути (без сегмента).
- **Никаких ручных действий не требуется.** Просто запустите плагин — всё мигрирует само.
### Что стоит сделать вручную
1. **Запустить обновление дерева** в панели FM (кнопка Refresh) — чтобы появились маркеры устаревших семейств.
2. **Переоткрыть проекты**, в которых уже загружались семейства — Stale Marker начнёт отображаться после первой загрузки семейства в этом проекте.
3. **Включить beta-канал** в настройках плагина (`IncludePrerelease = true`), если хотите получать будущие beta-релизы. По умолчанию флаг выключен.
### Возможные проблемы
- Если в FM много устаревших семейств (загружены в проект давно) — после обновления вы увидите много оранжевых маркеров. Это **не ошибка**, а индикация. Используйте контекстное меню «Обновить до текущей версии».
- При импорте большого количества `.rfa` (>32 файлов за раз) рекомендуется разбивать на пачки по 25-30 файлов — иначе Revit может заметно задуматься на открытии каждого документа.
