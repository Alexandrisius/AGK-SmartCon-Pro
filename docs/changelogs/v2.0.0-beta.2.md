# SmartCon 2.0.0-beta.2
> **Что нового с версии 2.0.0-beta.1** — серия критических исправлений **PipeConnect** (недетерминизм при соединении фитингов) и **FamilyManager** (Phase 24 — Stale Detection v2, мульти-выбор, диалог вложенных семейств), а также устранение **критического зависания UI в Revit 2023 (net48)**. Подготовлено **33 коммитами** за 13 дней (9 — 21 июня 2026).
---
## 🔥 Главное в этой версии
Этот релиз сфокусирован на **стабильности и предсказуемости** — там, где в beta.1 оставались шероховатости.
Самое заметное:
- **PipeConnect больше не выбирает «случайный» фитинг** из двух одинаковых — в Strategy 0 (центрирование по CTC) выбор стал детерминированным, ниппель между двумя одинаковыми вентилями теперь стабильно ставится на одну и ту же сторону. Закрыт баг #64.
- **Revit 2023 больше не зависает** после импорта семейств — исправлен критический баг `FireAndForget` UI-marshalling в net48: `Application.Current?.Dispatcher` возвращал `null`, а `Task.Run + ConfigureAwait(false)` сбрасывал UI SyncContext. Теперь диспетчер захватывается в ctor VM и маршалинг явный. Дерево каталога остаётся отзывчивым. Зафиксировано в **ADR-031**.
- **FamilyManager: Stale Detection v2** (Issue #69) — полная переработка механизма «устаревших семейств». Снапшот теперь корректно мержится по категориям, stale-маркеры сохраняются при обновлении дерева, скоупинг `Apply/Update` ограничен реальной категорией, а не «всем сразу». Добавлен **общий диалог загрузки вложенных семейств** (Issue #67).
- **Мульти-выбор в пакетном импорте** — можно выбрать сразу несколько строк и применить действие/категорию батчем.
- **Структурированное логирование Phase 2** — миграция с префиксов `[Cat]` на `BeginScope` + `OpId` + `Measure`. Файл лога читается в 10× быстрее, корреляция операций работает.
- **Сборка и обновления** — `Microsoft.Data.Sqlite` 8.0.28, `SO_REUSE_UNICASTPORT` для net48-апдейтера (фикс `WSAEACCES 10013`), CPM transitive pinning (фикс `NETSDK1152` при publish на net48).

## ✨ Новые возможности
### 🔀 PipeConnect: детерминированный выбор фитингов (Issue #64)
Самая неприятная категория багов в PipeConnect — **недетерминизм**: одна и та же операция «соедини два одинаковых вентиля» могла дать разный результат при повторных запусках.
- **Корневая причина:** после вычисления `Score` для fitting-коннекторов `OrderBy(p => p.Score).First()` выбирал произвольную пару — `cm.Connectors` имеет нестабильный порядок, и `ChangeTypeId` его перетасовывал.
- **Fix:**
  - `Score = distance(left.Origin → staticProxy.Origin)` — геометрически корректно (выбираем коннектор, ближайший к статическому элементу).
  - `.ThenBy(p => p.Fc1.Id)` — стабильный tie-breaker для теоретического edge-case с равной дистанцией.
  - Применено в `RevitFittingInsertService.AlignFittingToStatic` **и** `CtcResolutionService.ResolveConnectorSidesForElement` (оба страдали от того же бага).
- **Результат на реальном проекте:** 10 из 10 `ConnectTo` успешны, 8 из 8 Strategy 0 → `fc1 = conn[3]` (детерминированно), 0 `INVERSION` / `INVERTED` / `[ERR]` / `[WRN]`.
### 🟠 FamilyManager: Stale Detection v2 (Issue #69, Phase 24)
Полная переработка механизма «устаревших семейств» — закрыты критические баги первой реализации.
- **P0 — мерж снапшота по категориям.** `stale`-маркеры теперь сохраняются при обновлении дерева (раньше терялись для категорий без изменений).
- **P0 — `Apply/Update` скоупится реальной категорией**, а не применяется ко всему снапшоту (раньше можно было случайно «обновить» чужие семейства).
- **P0 — `MarkUpdated` в leaf-парах** (семейства на нижнем уровне теперь корректно помечаются как синхронизированные).
- **P1 — `LoadTreeAsync` переприменяет снапшот** к дереву после каждой загрузки — стейл-маркеры появляются сразу, без ручного refresh.
- **Архитектурная чистка:** убран `.rfa ES marker` (over-engineered, не давал ценности), структура стейл-детектора теперь соответствует плану Phase 24.
- **Тестовое покрытие:** +27 unit-тестов для snapshot POCO и SQL builder; документированы покрытые и непокрытые сценарии.
### 📂 Общий диалог загрузки вложенных семейств (Issue #67)
Вложенные семейства теперь импортируются через **единый общий диалог** (shared nested family load mode dialog) вместо разрозненных окон для каждого случая.
- Один диалог покрывает все сценарии загрузки вложенных семейств (из `.rfa`, из проекта, из каталога).
- Меньше «магии» в коде — пользователь видит, что произойдёт, до нажатия ОК.
- Поведение консистентно между `Import Active`, `Import Selected`, `Import Batch`.
### ☑️ Мульти-выбор в пакетном импорте
- Можно выделить **сразу несколько строк** в диалоге пакетного импорта и применить **действие** (`Новая версия` / `Перезаписать` / `Пропустить`) батчем.
- То же — для **категории**: выделил несколько семейств → назначил категорию одной операцией.
- Исправлены мелочи UI: рамка колонки `Types` в таблице, порядок кнопок в диалоге.
### 📝 Структурированное логирование Phase 2 (ADR-026)
- Полная миграция с префиксов `[Cat]` на `BeginScope("Cat", ...)` + `OpId` + `Measure`.
- **L8:** `FilePath` в scope теперь это `Path.GetFileName()`, не full path — в каждой строке лога на ~80 символов меньше.
- **L9:** все `Warn(...)` теперь заканчиваются `[Action: …]` — оператор сразу видит, что делать.
- DnD hot-fix: DnD-операции логируются без шума (идеальный лог, без «двойных» записей).
- Env override: `SMARTCON_LOG_LEVEL` позволяет поднять уровень в production-сборке без перекомпиляции.
- Зафиксировано в `docs/adr/026-logging-migration.md` + навыке `smartcon-logging`.
### 🛡️ net48 UI freeze — FireAndForget UI marshalling (ADR-031)
Критическое исправление, влияющее на **все** пользователи Revit 2019-2024.
- **Симптом:** после операции `FireAndForget` (например, сохранение извлечённого `.rfa`) UI панели FM «замирал» — LMB не реагировал, RMB «оживлял» панель.
- **Двухчастный root cause:**
  - `Application.Current?.Dispatcher` возвращал `null` в net48 Revit add-ins (UI-плагин живёт в AddinManifest, не в `Application`).
  - `Task.Run + ConfigureAwait(false)` сбрасывал UI SyncContext — даже если бы dispatcher был, `TreeNodes = rootNodes` всё равно выполнялся бы в thread pool.
- **Fix:** захватываем dispatcher в ctor VM (она создаётся на UI-потоке) и маршалим явно из `FireAndForget`.
- **Дополнительные правила:** нет двойного `LoadTreeAsync` вокруг save, минимум `Measure`/`Debug` на UI-потоке, не использовать `Clear() + Add()` вместо `TreeNodes = rootNodes` в net48.
- **Документация:** новый reference `fireandforget-freeze-net48.md` в skill `revit-wpf-compat`, ADR-031 с полным post-mortem.

## 🔧 Улучшения и исправления
### PipeConnect
- **Issue #64:** `IsKnownTypeDefinition` теперь использует **полный code+name+description** (а не только code) — устранены ложные срабатывания при матчинге типов.
- **Strategy 0:** distance-based score + стабильный tie-breaker (см. выше).
- Подтверждено на **1312 unit-тестах**: все зелёные, 0 регрессий.
### FamilyManager
- **net48 freeze (см. выше):** критическое исправление UI-marshalling — больше никаких «застываний» после импорта.
- **Tree refresh:** дерево корректно обновляется после сохранения извлечённого `.rfa` (раньше refresh мог не сработать).
- **net48 ContextMenu CanExecute:** workaround для `dotnet/wpf#4078` — `MenuItem.IsEnabled = false` явно выставляется в `CanExecute` net48 (раньше `MenuItem` оставался серым несмотря на true из `CanExecute`).

- **Batch dialog UI:** исправлена рамка колонки `Types` и порядок кнопок.
- **Debug:** добавлено логирование `RightClickSelect`, `paramType`, `CanCheck/CanExecute` — диагностика для issue в Revit 2023.

  - `dorny/paths-filter` обновлён в CI.

## 🏗️ Архитектурные изменения (для разработчиков)
### Принятые архитектурные решения (ADR)
- **ADR-026: Structured Logging Migration** — `BeginScope` + `OpId` + `Measure`, L8 (`Path.GetFileName` для scope), L9 (`[Action: …]` для `Warn`).
- **ADR-031: FireAndForget UI Marshalling in net48** — захват dispatcher в ctor VM, явный маршалинг из `FireAndForget`, явный запрет `Clear() + Add()` в net48.
### Рефакторинг (внутренние изменения, без влияния на UI)
- **Dispatcher захватывается в ctor** `FamilyManagerMainViewModel` — больше нет зависимости от `Application.Current?.Dispatcher`.
- **`FakeClock` дедуплицирован** в shared `TestDoubles/` — один источник истины для тестов.
- **Snapshot POCO вынесен в отдельный namespace** (`StaleDetection.Snapshot`) — чистая зависимость от Core, нулевая зависимость от Revit.
- **SQL builder** для стейл-детектора вынесен из VM — тестируем без Revit.
- **`DEBUG`/`TRACE` для custom configurations** — добавлены в `Directory.Build.props`.
### Контрибьюторам
- Перед любым изменением `FamilyManager` — загляните в `.agents/skills/revit-wpf-compat/references/fireandforget-freeze-net48.md` (полный case study) и ADR-031.
- При добавлении лог-вызовов — соблюдайте L8/L9 из skill `smartcon-logging`. `Warn` без `[Action: …]` = PR-rejection.

## 🔄 Обновление с 2.0.0-beta.1 → 2.0.0-beta.2
### Автоматическая миграция
- **Schema v10** БД применяется автоматически при первом запуске (изменения для Stale Detection v2 — новые индексы, расширенный snapshot).
- **Никаких ручных действий не требуется.** Просто запустите плагин — всё мигрирует само.
### Что стоит сделать вручную
1. **Перезапустить Revit** после обновления — обязательно для применения фикса `FireAndForget` (старый AppDomain мог «помнить» зависший UI SyncContext).
2. **Запустить обновление дерева** в панели FM (Refresh) — снапшот v2 применится и stale-маркеры пересчитаются по новой логике (Phase 24 корректнее различает «изменилось содержимое семейства» и «изменилась категория»).
3. **Проверить PipeConnect на сложных сценариях** — два одинаковых вентиля, два одинаковых фитинга. Теперь выбор стабильный.
### Возможные проблемы
- Если после обновления панель FM по-прежнему «замирает» — это **кэш AppDomain**. Полное закрытие Revit и запуск заново (не просто смена документа) решает проблему.
- При первом запуске после миграции Stale Detection может пересчитывать снапшот несколько секунд на больших каталогах (>500 семейств) — это нормально, кэш запишется в БД.
### Откат
- Если beta.2 не подходит — откат на beta.1 через `SmartCon.Updater` (Downgrade). БД совместима (схема v10 понимает данные v9).
