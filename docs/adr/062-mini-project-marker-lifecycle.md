# ADR-062: Маркер эталонных мини-проектов — безопасный жизненный цикл документа (Issues #186, #188)

**Date:** 2026-07-31
**Status:** accepted
**Related:** Issue #186, #188, #189, ADR-061 (system family sync), I-16 (managed storage immutability), ADR-027 (staging мини-проектов)

## Context

Эталон системного семейства FamilyManager — мини-проект `.rvt` в managed storage
(ADR-027). Куратор открывает его командой «Редактировать», правит и жмёт
«Импорт активного файла», чтобы создать новую версию. До этого ADR приложение
не отличало мини-проект от реального рабочего проекта пользователя, что
создавало три класса опасных сценариев:

1. **Закрытие документа после импорта.** Для loadable `.rfa` после импорта
   семья закрывается, фокус возвращается в проект (`CloseFamilyDocumentAsync`).
   Для системных — нет: мини-проект оставался открытым и активным. Но слепое
   закрытие «активного документа после импорта» недопустимо: «Импорт активного
   файла» легально запускается и на рабочем проекте — его закрытие уничтожило
   бы несохранённый прогресс.
2. **Сохранение эталона.** Куратор правит мини-проект v1 чтобы создать v2;
   импорт делает `SaveAs` в новый путь. Любое программное сохранение открытого
   мини-проекта перезаписало бы v1 (нарушение I-16). Закрытие обязано быть
   строго `Close(false)`.
3. **Автопереключение активной БД.** `ActiveDocumentChangeNotifier`
   (ViewActivated) переключал базу при активации мини-проекта — куратор мог
   не заметить и загрузить новую версию в чужую (дефолтную) базу.

## Decision

### 1. ES-маркер — единственный авторитетный признак мини-проекта

Схема `SmartCon_MiniProject_v1` (поля: SchemaVersion, CatalogItemId,
MarkedAtUtc) на элементе `DataStorage` («SmartCon.MiniProject») — по
рекомендации Jeremy Tammik: DataStorage вместо ProjectInfo избегает
element-ownership конфликтов в workshared-файлах и коллизий с другими
плагинами. Пишется **до `SaveAs`** в единственной точке staging
(`CreateCleanProjectWithTypesAndInstances`) — маркер переживает
закрытие/переоткрытие файла. Сервис `IMiniProjectMarker` (Core) /
`RevitMiniProjectMarker` (Revit): `MarkAsMiniProject`, `IsMiniProject`,
`ReadCatalogItemId`.

### 2. Двухфакторный guard закрытия (#186)

После успешного «Импорта активного файла» `CloseMiniProjectAfterImportAsync`
закрывает активный документ ТОЛЬКО когда выполнены **оба** условия:
ES-маркер присутствует **и** путь — форма managed storage
(`MiniProjectPathPattern`). Второй фактор закрывает fork-сценарий
(adversarial review M1): мини-проект, сохранённый через «Save As» в рабочую
папку как зерно нового проекта, маркер сохраняет, но managed-путь теряет —
закрывать его нельзя, это уже работа пользователя. Закрытие всегда
`Close(false)`. «Импорт выделенных элементов» не закрывает ничего.

`Document.Close` запрещён на активном документе, поэтому фокус сначала
переносится на рабочий проект, выбранный чистой логикой `WorkProjectSelector`
(исключает семьи, links, мини-проекты, сам эталон). Если рабочего проекта
нет — создаётся пустой `NewProjectDocument` вместо `PostableCommand.Close`:
модальный «Сохранить?» рисковал перезаписать v1.

### 3. Мини-проекты не влияют на автопереключение БД

`ActiveDocumentChangeNotifier` игнорирует маркированные документы (ES **или**
path-fallback для legacy-файлов без маркера) в `ViewActivated` и
`DocumentSaved(As)` — активная база остаётся той, что была до открытия
эталона. Path-fallback допустим здесь (обратимая операция), но НЕ в guard
закрытия (необратимая).

### 4. Legacy-файлы без маркера

Мини-проекты, созданные до фичи, маркера не имеют: автопереключение БД для
них работает через path-fallback, а закрытие — нет (безопасный отказ).
Полный backfill маркера во все версии — отдельная задача актуализации БД
`mini-project-marker-v1` (Issue #189): MakeActive может откатить на любую
версию, поэтому маркер нужен в каждом файле-варианте.

## Consequences

**Положительные:**
- UX-цикл «Редактировать → правка → Импорт активного файла → возврат в
  рабочий проект» симметричен loadable `.rfa`-флоу; эталон невозможно
  перезаписать программно.
- Активная база не «убегает» в дефолтную при редактировании эталона —
  причина молчаливых импортов не в ту базу устранена.
- Маркер переживает reopen (доказано интеграционным тестом
  `Marker_SurvivesSaveAsAndReopen`).

**Отрицательные/риски:**
- Legacy-мини-проекты не закрываются автоматически до backfill (#189).
- ES путешествует с файлом через SaveAs — осознанно компенсируется
  двухфакторным guard'ом (fork-защита).

**Покрытие:** 21 юнит-тест (WorkProjectSelector, MiniProjectPathPattern) +
7 интеграционных (маркер: запись/чтение/reopen/идемпотентность).
