# ADR-060: Full-immediate редактор категорий — отказ от draft-модели

**Date:** 2026-07-29  
**Status:** accepted  
**Related:** ADR-059 (Import Validation Gate), I-14

## Context

Редактор категорий (CategoryTreeEditor) изначально работал по draft-модели:
все правки (создание/rename/move/delete категорий, привязки атрибутов)
копились в памяти и коммитились по OK; Cancel откатывал. Практика показала
системные UX-дефекты этой модели:

1. **Нельзя работать без «сохрани и переоткрой»**: созданная категория —
   черновик с temp-id, привязать атрибуты и настроить правила валидации
   до OK невозможно (binding не существует в БД, правилам не к чему
   привязываться).
2. **Импорт пакета невидим до переоткрытия**: категории уходили в draft,
   атрибуты — сразу в БД, bindings/rules — в `_pendingBindingImports` до OK;
   чек-боксы привязок и бейджи правил не отображались.
3. **Частичный rollback**: Cancel «откатывал» не всё (атрибуты, записанные
   при импорте сразу, оставались) — модель обещала то, что не делала.

Исследование паттернов (SAP Fiori draft handling, Quay edit-buffer,
DB-редакторы DBeaver/DataGrip) и попытка гибрида (draft для категорий +
immediate для привязок) показали: частичный draft хуже обоих крайностей —
две модели персистентности в одном окне непредсказуемы.

## Decision

**Full immediate**: каждая операция редактора пишет в catalog.db немедленно:

- категории: create / rename / move / delete (delete — с confirm,
  каскад bindings/rules по FK, `catalog_items.category_id` сбрасывается
  репозиторием);
- привязки атрибутов: toggle создаёт/удаляет binding сразу — щит правил
  активен мгновенно;
- импорт metadata-пакета: атомарный коммит (категории → атрибуты →
  привязки → правила, дедуп по FullPath/имени/binding) + перечитывание
  редактора из БД;
- унаследованные binding'и защищены гардом `IsInherited` — unbind через
  дочернюю категорию невозможен (binding принадлежит родителю).

Драфт-машинерия (`_bindingChanges`, `_pendingCategoryDeletions`,
`_pendingBindingImports`, `IsNew/IsDirty/IsDeleted`, `HasUnsavedChanges`,
tempToRealId-маппинг) удалена целиком. Кнопки OK/Отмена заменены одной
**«Закрыть»** — потерять при закрытии нечего, confirm'ы при закрытии нет.

Cancel-семантика пожертвована осознанно: каждая операция либо обратима
вручную (переименовать обратно, переключить привязку), либо подтверждается
диалогом (удаление категории, отвязка атрибута с правилами). Это модель
DB-редакторов (DBeaver/DataGrip), а не диалога-формы.

## Consequences

- UX: нет состояний «не сохранено/не видно до переоткрытия»; импорт виден
  сразу; правила настраиваются на свежей категории без промежуточного OK.
- Код: −2 файла-драфта, −6 мёртвых свойств, упрощённые ConfirmClose и
  `OpenCategoryEditorAsync` (refresh главного дерева после закрытия
  модального диалога вместо события `Saved`).
- Тесты переписаны под immediate-семантику (create/rename/delete/move/
  bind/unbind пишут сразу).
- `AttributeLibraryViewModel` сохраняет свой draft — отдельный диалог со
  своей моделью «Сохранить/Отмена»; её унификация — отдельное решение.
