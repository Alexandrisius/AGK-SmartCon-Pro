# ADR-067: Dependency Guard — запрет удаления зависимостей, на которые ссылается любая версия родителя (E5, #213)

**Date:** 2026-08-06
**Status:** accepted
**Related:** Issue #213, #207 (EPIC), ADR-066 (модель family_dependencies), ADR-041 (версии)

## Context

После E1 (#208) фитинги-зависимости — полноценные элементы каталога, связанные
с родителями через `family_dependencies`. Удаление фитинга из каталога молча
убивает связи (FK CASCADE) → sync родителя деградирует до fallback-имени с
NotConverged, а архивная версия родителя перестаёт быть самодостаточной.

Вопрос владельца: «какой смысл иметь старую версию трубы, если она не сможет
загрузить фитинги? — получается неполноценное семейство висит как мусор».

Рассматривались две семантики guard'а удаления:
1. **Активные блок / архивные warn** — блокировать удаление только при ссылке
   с активной версии; архивные — confirm с предупреждением.
2. **Блок по любой версии** — нельзя удалить фитинг, на который ссылается
   любая версия любого родителя; освобождение — через удаление версии или
   родителя.

## Decision

**Семантика 2 — жёсткий блок по любой версии.** Обоснование владельца:
версия родителя, неспособная собрать себя целиком (её зависимости удалены),
— мусор в каталоге. Блок по любой версии делает «битую архивную версию»
структурно невозможной: каждая хранимая версия родителя всегда полноценна,
откат (MakeActive) всегда имеет живые фитинги для sync.

Семантика 1 отвергнута: «предупреждение об откате» легализует мусорные
версии; экономия (не держать старые фитинги) несущественна против цены
неработающего отката.

### Правила

- **Guard — item-level**: нельзя удалить элемент каталога с хотя бы одной
  входящей связью (любая версия любого родителя, любой `dependency_kind`).
  Блок-диалог со списком «родитель (версии)». Применяется ко всем точкам
  удаления items (дерево, batch, purge).
- **Освобождение**: удаление версии родителя (окно свойств) или родителя
  целиком → CASCADE убивает связи → ребёнок свободен, если других ссылок нет.
- **Версия ребёнка** удаляется свободно: связь ссылается на item ребёнка
  (не на его версию), активной становится другая версия — родитель остаётся
  работоспособен (философия активной версии, ADR-066 §3).
- **Переимпорт родителя**: связи новой версии замещаются (Replace);
  архивные версии сохраняют свои ссылки — их фитинги остаются залочены
  до удаления архивных версий (by design, не «заложники»: они обслуживают
  полноценность архивных версий).
- **UI**: скрепка-индикатор на leaf-узле + тултип со списком родителей и
  версий (batch reverse-запрос, индекс `ix_family_dependencies_child`).

## Consequences

- Каталог никогда не содержит версий родителей с мёртвыми зависимостями.
- Удаление старого фитинга требует сначала почистить версии родителя —
  осознанное трение, принятое владельцем.
- E2 (shared nested, #209) получает guard бесплатно (та же таблица, любой
  `dependency_kind`).
- Реализация: E5 (#213) — reverse-запросы репозитория, индикатор в дереве,
  guard во всех командах удаления, юнит/интеграционные тесты.

## As-built (2026-08-06, ручной тест владельца пройден)

- Reverse-запросы: `GetReferencingParentsAsync` + `GetReferencingParentsBatchAsync`
  (DISTINCT по (parent, version) — kind-дубликаты схлопываются; IN-параметры,
  индекс `ix_family_dependencies_child`).
- Guard-точки: `DeleteFamilyAsync` (единая команда ПКМ/кнопки) — блок-диалог
  через стилизованный `ShowInfo` (НЕ MessageBox).
- **Purge-guard упразднён (#133, решение владельца 2026-09-09):** мусорный
  фитинг (managed-файла физически нет) НИКОГДА не подгрузится в трассировку —
  связи на него мертвы. `PurgeMissingAsync` теперь удаляет такой item, а
  `family_dependencies` FK CASCADE сбрасывает ссылки родителей; результат
  (`PurgeMissingResult.ResetRoutingLinks`) несёт пары «фитинг × родитель»
  для предупреждения о stale-трассировке в проекте, а затронутые родители
  получают значок-фантом в дереве (клик → вкладка «Трассировка»). Guard
  живого удаления (`DeleteFamilyAsync`) не изменился.
- Guard fail-safe: ошибка чтения связей = блок удаления (Error + диалог),
  не молчаливое удаление.
- Скрепка: `IsDependencyReferenced` + минимальный тултип «Семейство» (v2)
  (без префикса и метки активной — решение владельца; метка «активная»
  только в блок-диалоге). Batch-пересчёт в `LoadTreeAsync`; инвалидация
  после удаления версии — флаг `VersionsChanged` (диалог свойств может
  закрыться Cancel'ом — дерево всё равно перестраивается).
- Освобождение (FK CASCADE) доказано юнит-тестами на настоящем провайдере
  (`DeleteVersionAsync`/`DeleteItemAsync` с PRAGMA foreign_keys=ON).
