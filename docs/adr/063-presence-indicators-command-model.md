# ADR-063: Индикаторы присутствия в проекте и per-type командная модель (Issues #187, #185)

**Date:** 2026-07-31
**Status:** accepted
**Related:** Issue #187, #185, ADR-061 (sync), ADR-030 (stale-detection v2), ADR-062 (маркер мини-проектов)

## Context

После ADR-061 пользователь получил sync системных типов, но не видел в дереве
каталога: какие типы уже есть в активном проекте, какие из них устарели,
и что делают команды «Загрузить в проект» / «Разместить» / DnD (внутри —
sync эталона, а не копирование). Ручной тест выявил: синие галочки «не
наш стиль», бейджи пропадали и появлялись при каждом LoadTree, не
обновлялись при переключении документа без смены базы, а одиночная
«Обновить» типа не гасила stale-индикатор.

Отдельная проблема: после импорта новой версии эталона пользователь обязан
был вручную жать «Проверить», чтобы увидеть устаревание рабочего проекта
(#185).

## Decision

### 1. Трёхзначные точки вместо иконок-галочек

По исследованию Exa (Carbon Design System — shape indicators, JetBrains —
file status colors) — Ellipse 8px с радиальным градиентом (glow, не плоская
заливка): **серая** — тип не загружен в активный проект, **синяя** —
загружен и актуален, **оранжевая** — загружен, но устарел. Модель
`TypePresenceState` (Core) вычисляется из двух независимых фактов:
присутствие (`IsInProject`) и свежесть (`IsStaleInProject`). Узел семейства
бейдж не получает (решение владельца — «семейство пока не трогать»).

### 2. Presence-снимок документа с кэшем (анти-мигание)

`ProjectPresenceSnapshot` — immutable снимок: системные типы (family, name)
+ legacy-имена по категориям + loadable семьи/символы (один
`FamilySymbol`-коллектор покрывает оба среза). Вычисляется внутри
ExternalEvent над ПОЛНЫМ каталогом (НЕ search-scoped — иначе очистка
поиска возвращала мигание), кэшируется по пути документа и применяется к
свежепостроенным узлам дерева ДО пересчёта — бейджи не мигают при каждом
LoadTree. Документ-семья (.rfa) пропускается. Переключение документа без
смены базы пересчитывает бейджи на месте (OnActiveDocumentChanged).

Системное семейство «в проекте» = rollup хотя бы одного типа (у системных
нет LoadFamily — они синхронизируются).

### 3. Per-type stale-карта (оранжевая точка)

`StaleDetector` хранит `_systemTypeStaleByType` (catalogItemId →
«FAMILY|NAME» → bool) из обоих путей проверки; loadable-типы наследуют
leaf-флаг `IsStale` (stale loadable — свойство всей семьи). Точечный сброс
`MarkSystemTypeUpdated` после sync одного типа — оранжевая точка гаснет
сразу, без полной «Проверить».

### 4. Командная модель узла типа по состоянию точки

| Точка | Команды |
|---|---|
| Серая | только «Разместить» |
| Зелёная | «Разместить» + «Обновить» |
| Оранжевая | только «Обновить» |

«Обновить» типа — единая команда: системный тип — sync по ADR-061,
loadable — обновление семьи с сохранением загруженных типов (#101;
per-symbol overwrite через Revit API невозможен). На семействе команда
«Обновить» переименована в **«Обновить все типы»** — контраст с точечной.

### 5. Автоматическая stale-проверка после импорта (#185)

После успешного batch-импорта (оба пути) и одиночного loadable-импорта
(включая MakeActive — откат версии честно показывает stale) запускается
одна проверка затронутых элементов против АКТИВНОГО документа — после
закрытия мини-проекта это рабочий проект с маркерами предыдущей версии.
UX-цикл «обновил эталон → сразу вижу ⚠ → жму „Обновить“» замкнулся без
ручной «Проверить». Проверка держит тот же guard `IsStaleCheckInProgress`,
что ручная (гонки исключены), элементы, отсутствующие в проекте,
пропускаются (не stale).

## Consequences

**Положительные:**
- Пользователь видит состояние каждого типа одним взглядом; команды
  соответствуют состоянию; семантика «синхронизировать» вместо «копировать».
- Ноль мигания бейджей при LoadTree/поиске/переключении документов.
- Индикаторы обновляются на каждом событии жизненного цикла: импорт,
  sync, stale-проверка, смена документа, смена базы.

**Отрицательные/риски:**
- До первой «Проверить» синяя точка означает «присутствует, актуальность
  не проверялась» (принятое допущение, отражено в тултипе).
- Loadable per-symbol обновление невозможно (Revit API) — «Обновить» типа
  обновляет семью целиком с сохранением типов.

**Покрытие:** юнит — `FamilyTypeNodePresenceTests` (5), SearchAsync
RevitCategoryId regression (1); интеграционные R25 83/83; adversarial
review трёх волн (M1/M2/L1-L9 + partial-snapshot) — чисто.
