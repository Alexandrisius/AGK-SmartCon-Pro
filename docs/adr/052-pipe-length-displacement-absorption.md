# ADR-052: Гашение смещения сети длиной трубы (per-level absorption)

**Date:** 2026-07-19 (rev. 2026-07-20 — per-level модель заменила eager-обход поддерева)  
**Status:** accepted  
**Related:** ADR-003 (TransactionGroup), ADR-009 (Vec3 в Core), ADR-043 (PipeConnect модальность)

## Context

При подключении уровня сети в PipeConnect (кнопки `+` / «Подключить всё») элемент
отсоединялся от сети, сдвигался как жёсткое тело на вектор выравнивания `v` и
переподключался. На следующем уровне то же повторялось для его соседей — смещение
протаскивалось через весь граф: подключение одного семейства со смещением 20 мм
сдвигало **всю систему** (например, отопление здания) на 20 мм. Физически такая
корректировка выполняется изменением длины одной трубы, а не переносом всей сети.

Ограничения Revit API (Exa-исследование: Autodesk forum 6857472, The Building
Coder rolling offset, revitapidocs `Pipe.Create`):

- Длина трубы меняется только присваиванием новой кривой:
  `((LocationCurve)pipe.Location).Curve = Line.CreateBound(p0, p1)` —
  `LocationCurve.Length` read-only.
- Жёсткий минимум длины MEPCurve — 1/10" (~2.54 мм); ниже — `ArgumentException`.

### Почему eager-модель отвергнута (3 полевых бага за один день)

Первая реализация распространяла смещение вглубь поддерева сети eagerly
(планировщик `DisplacementAbsorptionPlanner` + `BuildAbsorptionSubtree`):

1. **Весь узел двигался за один уровень** (`moves=21`) — ветки без поглощающих
   труб сдвигались «впрок», ломая поуровневый UX.
2. **Не-трубопроводные коннекторы** (электрика на насосе) попадали в план и
   теряли соединения («connector lost»).
3. **Асимметрия:** уровень 6 подключал сразу 9 элементов (включая трубы уровней
   12–13, которым потом «нечего было подключать»), а откат шёл поэлементно.
   Бухгалтерия откатов (многоуровневый restore, ConnectedLevel) разрасталась
   без надежды на консистентность.

## Decision

### Per-level модель: труба гасит смещение на СВОЁМ уровне

Смещение распространяется по уровням классическим потоком — по одному элементу
за инкремент (фитинги и семейства двигаются жёстко, как раньше). Единственное
отличие: когда инкремент доходит до элемента, который **сам является прямой
трубой**, и его выравнивание — чистая трансляция, труба **меняет длину вместо
перемещения**:

- ближний к родителю конец `LocationCurve` следует за вектором выравнивания `v`
  (совпадает с коннектором родителя),
- дальний конец получает только непоглощённый остаток `v - axis·absorbed`
  (при полном поглощении — ноль, propagation останавливается).

Остаток (частичное поглощение, перпендикулярная составляющая) обрабатывает
следующий уровень классически. Итоговая геометрия после обработки всех уровней
совпадает с eager-моделью, но достигается поэлементно — вперёд и назад
симметрично: один уровень = один элемент = одна undo-операция. Никакого обхода
поддерева, никаких кросс-уровневых снапшотов.

Математика (`PipeLengthAbsorber.Compute`, pure Core, Vec3):

```
axis     = normalize(far - near)      // near — конец ближе к коннектору родителя
axial    = dot(v, axis)
absorbed = axial > 0 ? min(axial, max(0, length - minPipeLength)) : axial
nearDelta = v
farDelta  = v - axis * absorbed
```

- Укорочение ограничено минимальной монтажной длиной; удлинение — нет.
- Перпендикулярная труба вырождается в чистую трансляцию (`absorbed ≈ 0`).
- Поворот в выравнивании → классический rigid align (труба поворот не гасит).

### Минимальная длина трубы — 100 мм (хардкод)

`PipeAbsorption.MinPipeLengthMm = 100.0` в `SmartCon.Core/Constants.cs`,
`MinPipeLengthFt = 100 / 304.8` (I-02: Core работает в decimal feet, конвертация
через точный фактор 1 ft = 304.8 mm). Жёсткий минимум Revit ~2.5 мм непригоден
монтажно; практика (Victaulic Field Installation Handbook, сварные/резьбовые
вставки) — короткие вставки от ~100 мм. Хардкод вместо настройки — осознанное
упрощение (не проверять частные случаи «труба заходит внутрь другого семейства»).

### Архитектура по Dependency Rule

| Слой | Артефакт | Роль |
|---|---|---|
| Core | `PipeLengthAbsorber` (Math, Vec3) | Pure math, 9 юнит-тестов |
| Core | `PipeAdjustOp` (Models) | Дельты концов кривой; id сырым `long` — тестируемость |
| Core | `PipeAbsorption` (Constants) | Лимит 100 мм (SI) + футы |
| PipeConnect | `ChainOperationHandler.TryAlignPipeByLength` | Перехват в `ProcessIncrementElement` внутри существующей `ITransactionGroupSession` (I-03/I-04) |

Точка интеграции одна: в `ProcessIncrementElement` вместо `AlignElement`
вызывается `TryAlignPipeByLength`; если элемент не труба, поворот обязателен или
установка кривой упала — классический `AlignElement`. Дальний конец трубы
переподключается не сразу, а на уровне downstream-соседа обычным потоком
(`FindEdgeToParent` → align → `ReconnectIncrementElement`) — поэтому
`DecrementLevel` остаётся поуровневым без изменений.

## Consequences

**Плюсы:**
- Сеть больше не сдвигается целиком: смещение останавливается на первой трубе
  вдоль оси; остальная сеть за трубой не двигается.
- Полная симметрия increment/decrement — откат поуровневый, как до фичи.
- Электрика и прочие домены не затрагиваются (обработка только своего элемента).
- Кодовая база прощё: нет планировщика поддерева, нет ConnectedLevel, нет
  многоуровневых откатов.

**Минусы / ограничения:**
- Повороты не гасятся (физически невозможно длиной трубы) — rigid align.
- FlexPipe и непрямые кривые не участвуют (только `Line`).
- Гашение применяется на уровнях сети и при начальном выравнивании динамика
  (см. Addendum 2026-07-20b ниже).

## Addendum 2026-07-20b: гашение при Init для трубы-динамика

Полевой тест показал пробел: при подключении **трубы как динамического элемента**
к статическому фитингу `AlignDynamic` всегда двигал её жёстко (`Align: Move
offset=99,31mm`), после чего уровень 1 (ниппель) догонял её жёстким сдвигом —
сеть тянулась и рвалась, хотя смещение шло точно вдоль оси трубы и могло быть
поглощено её длиной.

Решение: в `PipeConnectInitHandler.AlignDynamic` до жёсткого `MoveElement`
применяется та же проверка — динамик является прямой/гибкой трубой и
выравнивание чисто поступательное → `PipeAbsorptionApplier.TryApply`
(ближний конец к статике, дальний остаётся на сети). Уровень 1 получает
нулевой offset → запечатывание без единого движения сети. Повороты → rigid
(как раньше). Применение вынесено в общий `PipeAbsorptionApplier`
(SmartCon.PipeConnect/Services) — используется и Init-ом, и ChainOperationHandler
(убрано дублирование TryAbsorbStraightPipe/TryAbsorbFlexPipe).

Ранее задокументированное ограничение «начальное выравнивание dynamic не
меняется» относилось к дизайну для семейств; для труб оно снято этим
аддендумом.

## Addendum 2026-07-20c: MoveOrAbsorb — поглощение при ЛЮБОМ позиционировании динамика

Полевой тест вскрыл вторую половину проблемы: Init-поглощение удлиняло трубу
на полный offset до статика, но между статиком и динамиком вставляется фитинг
(произвольной длины) — и шаг `RealignAfterSizing` двигал динамик под фитинг
жёстко (`MoveElement` на длину фитинга), снова срывая сеть. Пользователь может
менять фитинг в окне, вставлять редьюсер, возможна композитная цепочка
fitting+reducer — длина вставленной цепочки заранее неизвестна.

Решение: единая точка `PipeAbsorptionApplier.MoveOrAbsorb(doc, transformSvc,
elemId, entryPoint, offset)` — поглощение для прямой/гибкой трубы (ближний
конец следует за offset, дальний неподвижен), жёсткий `MoveElement` для
остальных элементов. Применена во ВСЕХ местах позиционирования динамика под
вставленные элементы:

- `ConnectExecutor.RealignAfterSizing` — доводка динамика к `fitting.conn2`
  после вставки/ресайза фитинга (укорочение трубы на длину фитинга);
- `ConnectExecutor.CorrectDynamicPosition` — валидация перед ConnectTo
  (включая композит fitting+reducer — коррекция к `reducer.conn2`);
- `ConnectExecutor.ValidateDirectBranch` — direct-connect коррекция;
- `PipeConnectInitHandler.RunDirectConnectSizing` и `PipeConnectSizeHandler` —
  коррекция после смены размера динамика;
- VM-потоки вставки: `InsertReducerCore`, `ReflectElementCtc`,
  `Tx_PositionAfterReducerReSize`, `InsertFittingSilent`, `InitLegacyFlow`,
  `Tx_PositionAfterReducer`.

Итоговая семантика: Init удлиняет трубу до статика (полный offset), каждый
последующий шаг укорачивает её на длину вставленного элемента через
`MoveOrAbsorb` — дальний конец трубы и вся сеть за ним неподвижны на всём
протяжении сессии. Кеп 100 мм сохраняется: нехватка длины уходит остатком
дальше по цепи (обрабатывается уровнями). Пути с поворотами
(PipeConnectRotationHandler, Cycle) сознательно оставлены жёсткими — дугу
длиной трубы не погасить.

## Addendum 2026-07-20: FlexPipe + авто-пропуск мёртвых уровней

### FlexPipe

Гибкая труба гасит смещение через сеттер `FlexPipe.Points` (ReadWrite, Revit 2014+):
изменяется **только концевая точка** со стороны родителя (полный offset — flex
гнётся в любую сторону), все промежуточные точки сохраняются verbatim. Присвоение
`LocationCurve.Curve = HermiteSpline` для flex-элементов бросает исключение
(Autodesk forum 10671223) — поэтому только `Points`. Официальное поведение
(revitapidocs): «If the end points are changed, the connection will be maintained
by Revit automatically». Ограничение: длина ломаного пути после изменения ≥
100 мм, иначе rigid fallback. Снапшот расширен `ElementSnapshot.FlexPoints` —
откат восстанавливает форму целиком (`RestoreMepCurve`).

### Авто-пропуск и запечатывание мёртвых уровней

Когда труба полностью поглощает смещение раньше конца цепи, downstream-уровни
становятся no-op (offset ≈ 0, размеры совпадают) — пользователю незачем шагать
по ним вручную, а движку незачем их обрабатывать (снапшоты/disconnect/транзакции
на 1000-элементной сети ощутимы). Два механизма:

1. **Запечатывание (seal), основное.** `TrySealQuietChain` проверяет: все
   boundary-дети следующего уровня имеют нулевой offset, не требуют поворота и
   совпадают по радиусу с родителем, И все более глубокие piping-рёбра совпадают
   по радиусам (resize глубже = классическая обработка). Если тихо — одна
   транзакция `Tx_ChainSeal` переподключает boundary-рёбра, дальше сеть не
   трогается вообще, `+` и «Подключить всё» блокируются (`_chainSealed`),
   статус «Сеть скомпенсирована на уровне N». Проверка запускается после
   каждого инкремента, **при Init сессии и после каждой вставки/замены
   фитинга/редьюсера** (`TrySealChainIfQuiet`) — чтобы кнопки, которым нечего
   делать, были неактивны с самого начала; смена фитинга может и «распечатать»
   цепь (проверка возвращает false). Откат снимает флаг.
2. **Авто-пропуск (fallback).** Если запечатать нельзя (глубже есть resize),
   VM авто-пропускает мёртвые уровни при `+`/`−` по флагам `_levelDidWork`
   (обработка уровня выполняется — нужна для переподключения), со статусом
   «пропущено без изменений: N». Уровни с resize/reducer никогда не пропускаются.
