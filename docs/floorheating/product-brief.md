# FloorHeating — Product Brief

> **Изменчивый документ.** Одна страница: что строим и зачем. Правится свободно,
> без поправок. Математика — в [`kernel-spec.md`](kernel-spec.md) (стабильная).

## Задача

Проектировщик тёплых полов в Revit сегодня раскладывает петли вручную.
Модуль должен по области маскировки и паре труб (подача/обратка) **смоделировать
петли труб с фитингами** за секунды, а дальше — сам **подсказать шаг укладки** по расчёту.

## UX (целевой)

1. Пользователь выбирает область маскировки (FilledRegion, один контур) — зону укладки.
2. Выбирает подающую и обратную трубу — **их положение задаёт, где останутся «хвосты»
   контура** (начало и конец петли) для последующего подключения к магистрали.
3. Задаёт шаг d₀ (или оставляет «Авто» — когда появится расчётный модуль).
4. Опционально: направление закручивания (по / против часовой) — как в эталоне.
5. Опционально: чекбокс **«удалить предыдущую генерацию»** — идемпотентная регенерация:
   перед построением старые трубы этой зоны удаляются, чтобы можно было крутить
   параметры и перезапускать без ручной чистки (в эталоне такой флаг был).
6. Получает: петли улитки (Pipe + отводы), длины контуров, отчёт.

## Scope первой версии (MVP)

- Одна зона за запуск (зоны задаёт проектировщик — авто-деление помещения **не делаем**).
- Паттерн: **улитка** (DoubleLoop). Она же — единственный production-паттерн первой версии.
- Трубы + отводы в модели Revit, отчёт по длинам.
- Препятствия-колонны внутри зоны (обход естественный, без особой логики).

## Дальше (без дат, порядок = приоритет)

1. Расчётный модуль: d₀ и Lmax по теплопотерям/гидравлике (Physics Adapter → ядро).
2. Разбиение длинных петель по Lmax.
3. **Классическая змейка** — второй паттерн. В длинных узких зонах (коридоры)
   она практичнее улитки и алгоритмически проще; эталон её не умел вообще
   (только спираль + флаг направления).
4. Несколько зон за запуск, мультиконтурные области.

## Non-goals (явно)

- Автоматическое деление помещения на зоны контурирования.
- Гидравлика/теплотехника **внутри** геометрического ядра.
- «Двойная змейка», ring-based U-turn — никогда.
- 3D-вход: зона всегда плоская (проекция на уровень трубы).

## Архитектура (одна картинка)

```
Revit: FilledRegion + трубы
   │  (адаптер: границы → 2D-полигон, мм)
   ▼
FloorHeating Kernel (pure C#, docs/floorheating/kernel-spec.md)
   │  Loops (полилинии) + диагностика
   ▼
Revit-адаптер: Pipe.Create + NewElbowFitting, отчёт
   ▲
Physics Adapter (позже): теплопотери → d₀, Lmax → повторный вызов ядра
```

Ядро не знает о Revit (I-09): отдельный проект `SmartCon.FloorHeating`, зависимости —
только Clipper2. Revit-механика создания труб — по эталону [`warm_floor_python_original.md`](warm_floor_python_original.md).

## Критерий успеха MVP

- Улитка на простых и вогнутых зонах без self-intersection, параллельность ветвей 100–350 мм везде.
- На экстремальной геометрии — честный отказ с причиной, а не «красивая» неправильная геометрия.
- Время генерации типовой комнаты — до 1 секунды.
