## 1. Область ядра

### 1.1. Ядро ДЕЛАЕТ

Принимает плоский полигон зоны и параметры укладки, возвращает геометрию петель
трубы тёплого пола в виде непрерывных полилиний, с диагностикой и явными
непокрытыми зонами. Работает детерминированно, в миллиметрах, в 2D.

### 1.2. Ядро НЕ ДЕЛАЕТ (и никогда не будет)

- Не знает о Revit, трубах, фитингах, уровнях — это адаптер.
- Не считает тепло и гидравлику — это Physics Adapter, он **задаёт** d₀ и Lmax.
- Не делит помещение на зоны — зоны задаёт проектировщик.
- Не работает в 3D (вход — уже спроецированный 2D-полигон).

### 1.3. Принцип

> Ядро — детерминированная геометрическая машина: `D_work → Кольца → Traversal → Паттерн → Валидация`.
> Всё остальное — адаптеры по краям.

## 2. Контракт входа/выхода

### 2.1. Вход

```
KernelInput {
  Boundary   : Polygon2D          // внешний контур зоны, simple closed, мм
  Obstacles  : List<Polygon2D>    // препятствия (колонны), simple closed, может быть пустым
  Supply     : (Point, Direction) // точка подключения подачи и направление входа в зону
  Return     : (Point, Direction)? // точка обратки; null → совпадает с областью подачи
  Params     : KernelParams
}
```

**Валидация входа:** полигон замкнут и простой (без самопересечений);
`dist(Supply.Point, ∂Boundary) ≤ AttachMaxDist`; нарушение → явный `KernelFailure`, не исключение.

### 2.2. Параметры

| Параметр | Тип | Ограничение | Смысл |
|---|---|---|---|
| `d0` | мм | `[MinD0, MaxD0]` = `[200, 700]` | Шаг между осями соседних труб (пользовательский) |
| `WallClearance` | мм | `≥ 0` | Отступ трубы от стены |
| `ObstacleClearance` | мм | `≥ 0` | Отступ трубы от препятствия |
| `TubeDiameter` | мм | `> 0` | Наружный диаметр трубы |
| `Pattern` | enum | `SingleSpiral \| DoubleLoop` | Паттерн укладки |
| `Reverse` | bool | — | Направление обхода: по / против часовой (из эталона; дешёвая опция, влияет на сторону стыковки) |
| `EpsGeom` | мм | `> 0`, default `1.0` | Геометрический допуск |

### 2.3. Выход

```
KernelResult {
  Loops      : List<Loop>         // петли; каждая = непрерывная полилиния (List<Segment2D>)
  Uncovered  : List<Zone>         // непокрытые зоны с причиной (VANISH, NARROW, SPLIT без подводки)
  Diagnostics: { Rings, VanishCount, SplitCount, ShotFallbacks, CaseDistribution, ElapsedMs }
  Failure    : KernelFailure?     // явный отказ с причиной; Loops пуст
}
```

**Хвосты у подводки (контракт из эталона):** каждая петля **начинается у `Supply`
и заканчивается у `Return`** — свободные концы («хвосты») остаются в точках
подключения. Их подключение к реальным трубам магистрали — задача адаптера,
не ядра. Ядро гарантирует только, что хвосты лежат внутри D_work.

**Принцип громкого отказа:** ядро либо возвращает геометрию, удовлетворяющую всем
инвариантам (§7), либо `Failure` с понятной причиной. «Красивый мусор» запрещён.

## 3. Пайплайн

```
Boundary, Obstacles
  → [1] D_work        = Erode(Boundary, WallClearance + TubeDiameter/2)
                        ∖ ⋃ Dilate(Obstacle_i, ObstacleClearance + TubeDiameter/2)
  → [2] Кольца        R_0 = ∂D_work;  R_{k+1} = Offset(R_k, −d0)  до VANISH/SPLIT
  → [3] Traversal     Shot → Угловая компенсация → обход кольца → Step → …
                      (результат: Base — непрерывная полилиния от края к центру)
  → [4] Паттерн       SingleSpiral: Loop = Base
                      DoubleLoop:   Loop = ветвь_L(Base) + центр-мост + ветвь_R(Base) + подводка
  → [5] Валидация     инварианты §7; нарушение → Failure (не «частично хороший» результат)
```

Детерминизм обязателен: одинаковый вход → побитово одинаковый выход.
Никаких `Random`, `DateTime`, зависимости от порядка итерации хеш-таблиц.

## 4. Этапы ядра

### 4.1. Этап 1: D_work

Рабочая область, куда реально можно класть ось трубы.

- `D_work = Erode(Boundary, a_w) ∖ ⋃ Dilate(Obstacle_i, a_o)`,
  где `a_w = WallClearance + TubeDiameter/2`, `a_o = ObstacleClearance + TubeDiameter/2`.
- Реализация: полигонный offset и boolean difference (см. §8 «Движок»).
- Результат — одна или несколько связных компонент:
  - **1 компонента** — норма (в т.ч. с holes: колонна даёт «кольцевую» область, спираль обходит её естественно);
  - **несколько компонент (SPLIT)** — обходится только компонента, содержащая `Supply.Point`;
    остальные → `Uncovered` с причиной `SPLIT_NO_SUPPLY`.
- Компонента с минимальной шириной `< d0 + 2·Rmin` → целиком в `Uncovered` (`NARROW`).

### 4.2. Этап 2: Offset-кольца

```
R_0     = ∂D_work
R_{k+1} = Offset(R_k, −d0),  k = 0, 1, …
стоп: Offset пуст (VANISH) или Area < eps_min
```

- Кольца строятся **эрозией полигона D_work** (истинный полигональный offset) — не сдвигом
  вершин предыдущего кольца. Это принципиально: эрозия полигона корректна на вогнутостях,
  offset открытой полилинии — нет (§6.2).
- **VANISH** — нормальное завершение у центра; остаток площади → `Uncovered` (`VANISH`), это допустимо.
- **SPLIT** кольца на 2+ компоненты (узкая горловина) — каждая компонента становится
  самостоятельной под-спиралью; компоненты без достижимого supply → `Uncovered` (`SPLIT`).
- Инвариант: `dist(∂R_k, ∂R_{k+1}) = d0 ± eps`; кольца вложены: `R_{k+1} ⊂ R_k`.

**Золотые числа (регрессионный эталон, c_wall=50, D_tube=20, d0=200):**

| Фикстура | Колец | Длина Base |
|---|---|---|
| `square_5x5` (5000×5000) | 11–13 | 115–135 м |
| `rect_3x6` (3000×6000) | 6–8 | 75–90 м |

### 4.3. Этап 3: Traversal (Base)

Превращает набор колец в одну непрерывную полилинию. Три механизма.

#### 4.3.1. Shot (стыковка с кольцом)

- Луч из текущей точки `P` в направлении `V` (длина луча рабочая, напр. 1000 мм).
- **Режим 1:** если угол между `V` и направлением к началу сегмента `< α_parallel` (≈1°) —
  кандидат = начало сегмента.
- **Режим 2 (fallback):** ближайшая точка пересечения луча с сегментом
  (distance < eps, параметр не на самом конце сегмента).
- Из кандидатов — ближайший по параметру луча; кольцо циклически переупорядочивается,
  чтобы обход начинался с точки попадания.
- Если Shot не удался — `FallbackClosestPoint(P, Ring)`; если и он не даёт валидной
  стыковки — `Failure(STEP_IMPOSSIBLE)`.
- Диагностика: счётчики `Shots`, `ShotFallbacks` (fallback_ratio — часть контракта диагностики).

#### 4.3.2. Угловая компенсация (перед стыковкой кольца)

После reorder точка входа `S` лежит на первом сегменте. Углы и смещения:

```
θ₁ = угол(последний сегмент, первый);   θ₂ = угол(первый, второй)
leftOffset  = d0 / sin(θ₁)  если |sin(θ₁)| > 0.01  иначе d0     // guard: без деления на ~0
rightOffset = d0 / sin(θ₂)  если |sin(θ₂)| > 0.01  иначе d0
```

| Case | Условие (`p` = параметр S на первом сегменте длиной `L`) | Действие |
|---|---|---|
| **A** | `p < 2·leftOffset` | Первый сегмент — от S; последний укоротить на `leftOffset` |
| **B** | `p ≤ L − rightOffset` | Первый — от S; перемычка от конца кольца к точке «за S» на `d0` против направления |
| **C** | конец, `θ₂ < π` | Первый укоротить на `rightOffset`; циклический сдвиг влево |
| **D** | конец, `θ₂ ≥ π` | Второй укоротить на `leftOffset`; циклический сдвиг влево |

Лемма: после компенсации расстояние от конца обхода кольца до точки входа следующего = `d0 ± eps`.

#### 4.3.3. Step (перемычка между кольцами)

- Отрезок от конца обхода `R_k` до точки входа на `R_{k+1}` (через Shot по `stepDir`).
- **Обязательные проверки:** длина ≤ `2·d0`; сегмент целиком внутри D_work
  (**k-точечная проверка**, k=11 — проверка только midpoint запрещена: она пропускает
  диагональные мосты через всю комнату).
- Если midpoint/точки вне D_work — перебор 4 направлений (`stepDir, −stepDir, ⊥, −⊥`);
  ни одно не подошло → `Failure(STEP_INVALID)`.

**Известная слабость (зафиксирована, не блокер):** на экстремальной геометрии
(горловина ~700 мм, угол 15°) Step может честно падать в `Failure(STEP_INVALID)`.
Это предпочтительнее мусорного результата. Улучшение StepBuilder — отдельная поправка.

## 5. Этап 4: Паттерны

### 5.1. SingleSpiral (диагностический)

`Loop = Base`. Supply-half без обратки. Не является production-паттерном водяного
тёплого пола; существует как фундамент и база валидации ядра.

### 5.2. DoubleLoop — улитка (основной production-паттерн)

Подача и обратка параллельны на `d0/2`, обратка идёт между витками подачи.

#### 5.2.1. Конструкция (нормативная): Base + две ветви

```
Base  = Traversal(кольца)                        // §4.3, центральная ось улитки
LeftBranch  = ParallelCopy(Base, +d0/4)          // сдвиг каждого сегмента по левой нормали
RightBranch = ParallelCopy(Base, −d0/4)          // по правой; стыки — miter join (bevel fallback)
CenterBridge = LeftBranch.End → midpoint → RightBranch.End     // U-разворот в центре
Attach       = Supply.Port → обе ветви у входа; Return аналогично
Loop = LeftBranch + CenterBridge + Reverse(RightBranch) + Attach
```

Почему это корректно (и почему отвергнуты альтернативы):

1. **Обе ветви — сдвиги ОДНОЙ оси на ±d0/4.** Miter-shortening на вогнутых стыках
   (`(d0/4)·cot(полуугол)`) действует на обе ветви **симметрично** — они смещаются
   вместе, и расстояние между ними остаётся `d0/2` везде, включая угловые срезы.
   Проблема «44-мм hot-spot» (см. капсулу §5) устранена by construction.
2. **Запрещённая конструкция:** `Return = Offset(ClosedPolyline(Base), −d0/2)`
   (miter-offset замкнутой полилинии подачи, как в Python-эталоне и в нашей попытке
   Variant C). На вогнутом изгибе внутренняя кривая укорачивается на
   `offset·cot(полуугол)` = 41.4 мм для стыка 135° при d0=200 → нарушение нормы
   100 мм на каждом угловом срезе. Это свойство геометрии, не баг; Python-эталон
   живёт с ним в проде, мы — не хотим.
3. **Запрещённая конструкция 2:** `Reverse(Base)` — та же геометрия задом наперёд,
   не труба. Детектор: `Length(Loop)/Length(Base) = ровно 2.0` у заглушки;
   у честной улитки ∈ `[1.9, 2.0)` + два параллельных семейства сегментов.
4. **Miter join ветвей — с обязательной dedup-логикой:** на коллинеарных стыках
   (после нарезки сегментов) сдвинутые концы совпадают → добавлять **одну** вершину,
   иначе zero-length сегменты ломают downstream-проверки self-intersection.
5. **Центр:** внутреннее кольцо (радиус ~d0) не вмещает две ветви → хвост ветвей
   обрезается до ближайшей непересекающейся конфигурации, разворот — через midpoint,
   как в эталоне. Центральная непокрытая зона ≤ 350×350 мм — приемлема.

#### 5.2.2. Инварианты улитки (нормативные)

- **Параллельность:** для каждой согласованной анти-параллельной пары сегментов
  (left, right): `dist ∈ [MinParallelSpacing, MaxParallelSpacing]` = `[100, 350]` мм.
  Без исключений для угловых зон (в отличие от relaxed-критерия старого Variant C).
- **Центральный разворот:** `dist(LeftBranch.End, RightBranch.End) ∈ [100, 350]`.
- **Мосты:** каждый ≤ `2·d0`. **Непрерывность:** стыки < `EpsGeom`.
- **Нет self-intersection** — без толерантностей.
- `d0` вне `[200, 700]` → `Failure(D0_OUT_OF_RANGE)`.

### 5.3. Будущие паттерны (не нормативно, для ориентира)

- **Классическая змейка (boustrophedon):** параллельные проходы вдоль длинной стороны
  с U-разворотами 180° на границах; подача → обратка через последний разворот.
  Отдельный builder над тем же D_work; кольца не нужны. Оформляется поправкой
  к этому документу, когда будет дизайн.
  **Практический мотив:** в длинных узких зонах (коридоры) змейка **практичнее и проще
  улитки** — меньше изгибов, короче труба, легче укладка. Эталон был spiral-only
  (отсюда его флаг `reverse` как единственная «настройка формы») и коридоры ему
  не давались; для нас змейка — второй приоритет после улитки, не «когда-нибудь».
- **Никогда:** «двойная змейка»; ring-based U-turn (гибрид из старой спеки v2.0 §12).

## 6. Постобработка (опциональные этапы, вне критического пути)

### 6.1. Фаски (Chamfer)

Для двух соседних сегментов с углом `θ < π/2 − 0.05`:
`y = |(x/2) / sin(θ/2)|`, применять если `0 < y < len/2` обоих сегментов;
угол заменяется тремя сегментами (укороченный, скос, укороченный).
Переносится из эталона без изменений.

### 6.2. Склейка коллинеарных (Rebuild)

Соседние сегменты с углом ≤ 1° и разрывом < eps объединяются. Один линейный проход.

### 6.3. Разбиение по Lmax (будущее)

Разрез петли только на Step-перемычках или точках подводки. Оформляется поправкой.

## 7. Инварианты ядра (проверяются на каждом результате)

| Id | Инвариант | Проверка |
|---|---|---|
| I1 | Внутри D_work | каждый сегмент, **k-точечно** (k=11), не midpoint |
| I3 | Нет self-intersection | попарно не-смежные сегменты |
| I4 | Шаг витков | `dist(R_k, R_{k+1}) = d0 ± eps` |
| I7 | Детерминизм | повторный прогон = идентичный результат |
| I9 | Непрерывность | `dist(seg_i.End, seg_{i+1}.Start) < EpsGeom` |
| I10 | Валидность Step | Step ⊂ D_work, длина ≤ `2·d0` |
| I13 | Параллельность улитки | §5.2.2: `[100, 350]` мм на всех matched pairs |
| — | Макс. длина сегмента | `∀ s: len(s) ≤ 2·d0` (ловит сломанные Step) |

Нарушение любого — результат не выдаётся: `Failure` с кодом инварианта.

## 8. Численные константы и движок

### 8.1. Инженерные нормы (абсолютные, НЕ функции от d0)

| Константа | Значение | Обоснование |
|---|---|---|
| `MinParallelSpacing` | **100 мм** | перегрев поверхности при меньшем шаге (СНиП, теплоноситель 40–50 °C) |
| `MaxParallelSpacing` | **350 мм** | в бо́льший gap влезает ещё пара труб (100+150+100) → холодное пятно |
| `MinUTurnSpacing` | **150 мм** | bend radius PEX-16 = 75 мм × 2; обеспечивается монтажником, не ядром |
| `MinD0` / `MaxD0` | **200 / 700 мм** | чтобы `d0/2 ∈ [100, 350]` |

### 8.2. Геометрический движок

Полигональные offset/boolean — **Clipper2** (NuGet `Clipper2`, namespace `Clipper2Lib`,
Boost License, netstandard2.0 → net48 + net8 без изменений).

Боевые правила (проверены практикой):

- Только `PathsD` (double, мм) с `precision = 2`. Никогда не `Paths64` вручную.
- Эрозия: `Clipper.InflatePaths(paths, -delta, JoinType.Miter, EndType.Polygon)`;
  `Count == 0` → VANISH (норма); `Count > 1` → SPLIT.
- D_work с препятствиями: `Clipper.Difference(eroded, dilatedObstacles, FillRule.EvenOdd)`.
- **Открытые** пути через `InflatePaths` не offset'ить: возвращает один замкнутый
  «тубус», не параллельную кривую. Для ветвей улитки — ручной перпендикулярный
  сдвиг + miter join (§5.2.1).
- Не дублировать первую точку пути в конце (замыкание неявное).

## 9. Вырожденные случаи (каталог обязан быть покрыт фикстурами)

| Случай | Поведение ядра |
|---|---|
| `sin(θ) ≈ 0` в компенсации | guard → `offset = d0` |
| Сегмент короче offset | удалить; если вершин < 3 → VANISH |
| Shot не удался | FallbackClosestPoint → иначе `Failure(STEP_IMPOSSIBLE)` |
| Step вне D_work | перебор 4 направлений → иначе `Failure(STEP_INVALID)` |
| Узкая горловина (~700 мм) | SPLIT; компонента без supply → `Uncovered` |
| Острый угол (15°) | компенсация с guard; честный `Failure` допустим |
| Тонкая полоса (4000×500) | VANISH у центра → `Uncovered`, без падения |
| Длинный коридор (2000×10000) | float-стабильность, без NaN |
| Вогнутая форма (L) | полная поддержка; centroid-based эвристики **запрещены** |
| Препятствие-колонна | D_work «кольцом», спираль обходит естественно |

Эталонные фикстуры: `square_5x5`, `rect_3x6`, `bathroom_2x2_5`, `l_shape`,
`living_room_5x5`, `narrow_throat_700mm`, `vanish_center`, `acute_angle_15deg`,
`long_corridor_2x10`.

## 10. Стратегия валидации (без фаз и гейтов)

Ядро считается работающим, когда зелёные **все** проверки ниже. Они же — живой
регрессионный стенд; никаких отдельных «планов приёмки».

1. **Golden reference:** §4.2 (кольца/длины на square_5x5, rect_3x6).
2. **Инварианты §7** — на каждой фикстуре, обоих паттернов.
3. **Property-тесты:** детерминизм; `Reverse(Reverse(x)) = x`; площади колец монотонно убывают.
4. **Сценарный стенд + SVG:** каждая фикстура рендерится в SVG (контур, D_work, петли,
   легенда с метриками); визуальный осмотр обязателен — «SVG сгенерирован» ≠ «корректно».
5. **Строгость тестов:** запрещено ослаблять assert'ы без поправки к этому документу.
   Тест = спецификация; слабый тест = слабая спецификация.

## 11. Терминология (нормативная)

| Термин | Значение |
|---|---|
| **Улитка** | DoubleLoop: подача к центру, обратка между витками, параллельно `d0/2`. Production-паттерн |
| **Одиночная спираль** | SingleSpiral: supply-half. Диагностика |
| **Классическая змейка** | Параллельные проходы + U-turn 180°. Будущий паттерн (§5.3) |
| **D_work** | Рабочая область оси трубы после отступов |
| **Кольцо** | Замкнутый offset-контур `R_k` |
| **Base** | Центральная ось улитки — результат Traversal по кольцам |
| **Step** | Перемычка между соседними кольцами (≈ `d0`) |
| **VANISH / SPLIT** | Исчезновение кольца / распад на компоненты |
