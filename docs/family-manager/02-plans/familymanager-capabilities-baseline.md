# FamilyManager — Baseline возможностей (для ревью плана Cloud Catalog)

> **Назначение:** единая точка входа для ревьюеров мастер-плана Облачного каталога (ADR-075/076/077, `cloud-catalog-master-plan.md`). Фиксирует, что модуль уже умеет на момент 2026-08-25, чтобы аудит плана вёлся от фактов, а не от изучения кода.
>
> **Источники:** `docs/changelogs/v1.1.0 … v2.0.1-beta.9` (37 файлов), `docs/family-manager/README.md` (фазы, миграции V1–V31), заголовки ADR-014…073. Код `src/` намеренно не использовался.

---

## 1. Карта возможностей по темам

### 1.1 Управление базами (multi-DB)

- **Multi-Database**: создание, подключение, переключение, отключение, удаление нескольких каталогов. Хранилище — SQLite `catalog.db` + managed `.rfa` storage; база живёт в `%APPDATA%\SmartCon\FamilyManager\databases\{id}\` (ADR-014/015, Phase 12–13).
- **Виды баз**: *общие* (доступны из любого проекта) и *проектные* (привязка к имени `.rvt` по настраиваемому шаблону, автоактивация при открытии/Save/SaveAs подходящего проекта; несовместимая база блокирует Load/Place иконкой замка). `base_type` и `project_binding_json` хранятся в `database_meta` (V20/V21), поэтому тип переживает reconnect (v2.0.1-beta.1, #119; автоактивация при Save/SaveAs — beta.2). Конвертация общая ⇄ проектная одной командой (beta.6, #168).
- **SMB/сетевые диски**: SQLite в `DELETE` journal mode (не WAL) для совместимости с SMB (I-14, v1.9.0); роль Engineer подключается с `Mode=ReadOnly` — без journal-файлов на сетевом ресурсе (beta.5).
- **Ограничения**: удаление базы с read-only `.rfa` — рекурсивный сброс атрибута + retry, занятая папка уходит в `.trash` на очистку при следующем запуске (beta.1/2). `registry.json` сериализован от конкурентных записей (#171). Forward-compat гейт: `min_plugin_version` (V24, ADR-058) — старый плагин открывает обновлённую базу read-only с баннером «обновите плагин» (#173).

### 1.2 Импорт (все UC)

- **Единый пакетный импорт** (Batch Import v4 → modeless, ADR-048): таблица файлов (имя, версия Revit, размер, статус, действие), статусы `Новое / Существующее / Дубликат`, действия `Новая версия / Перезаписать текущую / Пропустить`, мульти-выбор строк, live-прогресс построчно, Stop→Resume/Close, сводка. Команды «Импорт папки» и «Импорт данных» удалены из UI — пакетный импорт покрывает всё (2.0.0).
- **UC-1/UC-2 — файлы/папки**: drag-and-drop `.rfa` на панель, выбор нескольких файлов, автоопределение версии Revit через BasicFileInfo (v1.6.0).
- **UC-3 — «Импорт активного файла»**: быстрый анализ (<1 сек на 200 семейств) без открытия `.rfa`, сводка «N системных категорий (M типов) и K загружаемых», импортируются **только размещённые** семейства (`OfClass(FamilyInstance)+GroupBy`, ADR-027); `.txt` Type Catalog активного семейства сохраняется (ADR-024).
- **UC-4 — «Импорт выделенных элементов»**: принимает любые элементы (системные категории + `FamilyInstance`), 5 фаз: анализ → подтверждение → подготовка → batch-диалог → диспетчеризация (2.0.0-beta.1).
- **Виртуальные метаданные**: batch-диалог открывается <1 сек для 50+ семейств — staging выполняется только после подтверждения (2.0.0-beta.3). Переименование строки пересчитывает статус New↔Existing через debounce 250 мс; Import ждёт завершения пересчётов (#135-beta.4).
- **Гейт валидации при импорте** (ADR-059, Phase 34): health-check `.rfa` без диалогов Revit (silent rollback, UC-1/UC-2), правила качества на binding'ах категорий (12 операторов, display-units-first), отчёт по каждой строке, одна битая строка не блокирует остальные; валидация срабатывает и при смене категории/DnD; единый копируемый отчёт о проверке (beta.9).
- **Ограничения**: COM-утечка при >32 файлов подряд устранена `Marshal.ReleaseComObject`, но рекомендованы пачки 25–30 файлов (2.0.0-beta.1); RBAC-проверка до открытия диалога; пробел перед `.rfa` и длинные пути отклоняются с понятным сообщением (#54).

### 1.3 Версионирование

- **Вкладка «Версии»**: все версии с датой/автором/количеством типов, переключение активной версии одним кликом, удаление неактивных, **per-version типы и атрибуты** — откат восстанавливает именно её данные (2.0.0-beta.4, ADR-041, schema V17–V19; `published_by` — V19).
- **Активная версия**: `SetActiveVersion` синхронизирует имя элемента с именем файла активной версии (beta.3, ADR-049). В диалоге импорта дубликата есть действие «Сделать активной».
- **OverwriteCurrent** (ADR-040, Phase 28): «Перезаписать текущую» обновляет содержимое без инкремента номера версии; работает для всех UC (активный `.rfa`, системные, выделенные) — 2.0.0-beta.4.
- **«Новая версия»** (бывш. «Инкремент версии»): следующий label `v2`, `v3`…, текущая переключается на новую.

### 1.4 Контент-хэш и дедупликация

- **Дедупликация по содержимому**: дубликат находится даже при переименовании, Save As, другой папке, импорте из проекта; строка-дубликат авто-помечается «Пропустить» (2.0.0-beta.4, ADR-039 → content_hash V16).
- **FHV2 (rename-invariant, ADR-049/050, Phase 32)**: имя файла исключено из хэша; hash-first dedup (хэш по всем версиям всех элементов, потом имя); cross-name дубликат — ⚠ + привязка через `forcedCatalogItemId`; миграция хэшей v1→v2 — user-initiated, modeless прогресс, chunk-коммиты, докачка.
- **FHV3 (ADR-056, Phase 33)**: локале-инвариантная категория (ordinal — RU/EN Revit дают один хэш), секции FACTS (PartType), FLAGS (Shared/WorkPlaneBased/…), CONN (коннекторы: домен/форма/размеры/SystemClassification/Origin 1e-4 ft/топология), STRUCT (CompoundStructure), ROUTING (RoutingPreferences), bbox+surface геометрия, экранирование; критическая задача `hash-v3` заменила `hash-v2` (#159).
- Далее по ADR: FHV4 (расширенная идентичность системных типов + трёхуровневый sync, ADR-065), FHV8V/FHV9 phantom-верификация вложенных (ADR-068), **FHV11 — lookup-таблицы входят в хэш** (правка CSV → новая версия, не «дубликат», #238, ADR-069).
- **Ограничение**: смена формата хэша = breaking, выкатывается через critical-задачу actualization engine (база read-only до пересчёта), без DDL-миграции.

### 1.5 Системные семейства

- Поддерживаемые категории: трубы, гибкие трубы, воздуховоды, гибкие воздуховоды, короба, лотки, стены (+ позже: футеровка воздуховодов, провода, ограждения, полы/потолки/крыши через CompoundStructure). Каждая категория — свой placement handler (2.0.0-beta.1; beta.8 #197/#199/#200).
- **Staged `.rvt` / мини-проекты**: системные типы размещаются реальными инстансами в staged-мини-проекте, который сохраняется в managed storage (immutable, I-16); маркер мини-проекта `es_marker_version` (V28, ADR-062) с задачей `mini-project-marker-v1`; мини-проекты не перехватывают авто-переключение активной БД и закрываются без «Сохранить изменения?» (#186/#188).
- **Locale-invariant идентичность**: `family_key` (V27, ADR-064) — RU/EN Revit видят одну системную семью.
- **Sync в проект на месте** (ADR-061, #104, beta.8): «Обновить» синхронизирует сегменты, материалы, правила трассировки, фитинги, слои конструкций **без удаления и повторного размещения**; точечное обновление одного типа; прогресс «N из M» в статусной строке.

### 1.6 Loadable семейства и Type Catalog

- **Bake-in Type Catalog** (ADR-033, Phase 26, заменила симуляцию ADR-032): типы из `.txt` переносятся в `.rfa` в топологическом порядке с восстановлением формул, результат `SaveAs` в managed storage; `.txt`-сайдкары в managed storage отсутствуют.
- Парсер `.txt`: RFC 4180, универсальная кодировка (кириллица), заголовок `parameter##TYPE##UNITS` с конверсией юнитов через `UnitUtils` (~30 алиасов, singular/plural/typo), StorageType выровнен с Revit; IFailuresPreprocessor по Tammik-паттерну глушит ошибки формул (2.0.0-beta.3).
- Извлечение **полного списка типоразмеров** per version; виртуальный сентинел `<default>` для бестиповых семейств (узел в дереве = имя семейства; #172, #223); команда «Перезаписать Type Catalog» в подменю обновления.
- Синхронизация типов при повторном импорте: DELETE+INSERT в одной транзакции — «фантомные типы» не остаются (#85, ADR-036, FK CASCADE V15).

### 1.7 Зависимости семейств

- **`family_dependencies`** (V29/V30, ADR-066, EPIC #207): связи parent→child для routing-фитингов и shared nested, включая embedded child version label (#209, ADR-068 — верификация вложенных в family-документе, self-heal ссылок).
- **Индикация**: скрепка в batch-импорте и в дереве (tooltip «Зависимость — нажмите для подробностей»); список остаётся плоским, один child — несколько родителей (as-built ADR-066 §E3).
- **Dependency Guard** (ADR-067, #213): запрет удаления семейства, используемого родителями (диалог «Удаление заблокировано» со списком версий родителей); блокировка импорта/загрузки родителя с устаревшей «зашитой» копией вложенного (только «Пропустить»).
- **Shared nested names persistence** (ADR-034, workaround REVIT-198137): таблица `family_nested_shared_families` (V13) + резолвер `RevitApi → CatalogDb → Placeholder` для Revit 2023/2024; для каталогов <2.0.0 — placeholder до повторного импорта (breaking 2.0.0).

### 1.8 Атрибуты, категории, правила

- **Attribute Extraction** (ADR-017, Phase 14): извлекаются **все** общие и системные параметры (не только привязанные к категории), хранятся с nullable `attribute_id`, fallback по `ParameterName` (V8); единицы форматируются по документу-владельцу, фикс RU-локализации «бары»→«бар» (#151–#153).
- **Библиотека атрибутов**: окно Attribute Library, пресеты извлечения per категория, импорт атрибутов из ФОП («From SP file», парсер секций *GROUP/*PARAM, черновики до OK, beta.5), автодополнение групп.
- **Category bindings** (full-immediate редактор, ADR-060, Phase 35): create/rename/move/delete и привязки пишутся сразу, без draft/OK; перемещённая категория не теряет привязки.
- **Validation gate** (ADR-059): правила на binding'ах (обязательные параметры, допустимые значения, 12 операторов, display-units-first), наследование вниз по дереву; карантин «Без категории» для read-only ролей; единый гейт на импорт/новую версию/DnD/свойства; metadata-пакет v3 переносит правила.
- **Автоназначение категорий** (ADR-070, #241, beta.9): группы условий (внутри — И, между — ИЛИ), условия по атрибутам и системным полям (Revit-категория, Тип детали, имя семейства); однозначное правило назначает сразу, неоднозначное — ⚠ с пикером кандидатов; побеждает самое глубокое правило; «Копировать условия предка»; правила путешествуют в metadata-пакете (совместимо с v4, ADR-075); таблицы V31.
- **Family Facts** (ADR-055, V22): реестр фактов, первый — Part Type («Тип детали») для 4 категорий фитингов с официальной RU-локализацией Autodesk; сентинелы «вычислено, но отсутствует»; факты не входят в хэш; задача `family-facts-v1` дозаполняет старые базы.
- **Metadata package** (export/import): атомарный коммит (категории → атрибуты → правила) + reload; переносит категории, атрибуты, validation-правила, auto-assignment правила между базами.

### 1.9 3D-превью, аватары, assets

- **3D Просмотр** (ADR-042, Phase 29): интерактивный вьювер (вращение/зум/панорама), геометрия извлекается при импорте per version, переключатель типов, материалы вложенных, smooth shading, камера сохраняется, coarse-only символика исключена, видимость по типу; работает R19–R25+. Собственный GLB 2.0 writer (без SharpGLTF) — фикс краша `System.Text.Json` на Revit 2021 и ориентации Z-up→Y-up (beta.2). Fallback: превью на лету из managed `.rfa`; `glb_state` (V23) — терминальный маркер «нет геометрии» против «вечной янтарной точки» (#157).
- **Avatar Crop** (ADR-047, Phase 30): диалог кадрирования (зум/панорама/свободные пропорции), производный `avatar.png` 560×420, единое превью 280×210 в свойствах и tooltip, инвалидация при смене/удалении primary (#131).
- **Assets**: привязка файлов (изображения/видео/документы/таблицы) к семейству, категории по расширению, миниатюры, «Привязать к версии», «Сделать основным» (звезда); GLB не попадает в общий список (beta.1, ADR-044). Preview не блокирует файлы (`CacheOption=OnLoad`+Freeze, #58).

### 1.10 Stale detection и presence

- **ES-маркер `SmartCon_FamilyVersion_v1`** (ADR-030, Phase 24): **единственное** ES-исключение — на `Family` в проекте пишутся `CatalogItemId`, `VersionLabel`, `LoadedAtUtc`, `SourceRevitVersion`; в `.rfa` не пишется. Жёсткий запрет ES для всего остального (README → «Жёсткий запрет»).
- **Stale Detection v2**: оранжевый маркер «[Устарело]» в дереве (батчевый SQL), мерж снапшота по категориям, скоуп Apply/Update по реальной категории, переприменение снапшота после LoadTree (2.0.0-beta.2, #69).
- **«Проверить» сверяет содержимое** (#180, beta.8): не только маркер — локальные правки семейства в проекте помечаются устаревшими с предупреждением о потере правок; учитывает частично загруженные мультитиповые семейства (#222/#225) и «осиротевшие» маркеры (#218); маркер ресинхронизируется после UC-3/UC-4 (#84).
- **Presence-индикаторы** (ADR-063, #187/#185): трёхцветная точка у типа (серый=не в проекте, голубой=актуален, оранжевый=устарел), клик = действие (Загрузить+разместить / Разместить / Обновить+разместить, сторож «никогда не размещать stale», #221); DnD устаревшего типа перезагружает из каталога; автопроверка после импорта.
- **Индикация недоступных**: замок + серый текст + тултип с причиной (Deprecated / RevitVersion-несовместимость); резолвер берёт старшую версию ≤ текущего Revit (beta.5).

### 1.11 RBAC

- Роли **Owner / BimMaster / Engineer** (ADR-022, Phase 20, schema V7): Owner — всё + управление пользователями и передача прав; BimMaster — импорт/редактирование/категории; Engineer — чтение + загрузка/размещение.
- Идентификация по Windows-логину + машине; Ban без удаления данных; первый открывший базу после миграции V7 становится Owner; `CanExecute`-валидация всех команд (включая DnD #57); Engineer — read-only SQLite на SMB + гейт команды «Обновить базу» по CanEdit (beta.5); команды конвертации/настройки проектных баз скрыты от Engineer (#168/#169).

### 1.12 Загрузка в проект и размещение

- **LoadToProject / Place разделены**: проверка `VersionGuid` — «Уже актуальная версия» без перезагрузки; `FamilyLoadStatus` (Loaded/Updated/Current/Failed); Place активна только после загрузки (#54-beta.2, CanPlaceType).
- **Per-type размещение**: контекстное меню типа, presence-точка как третий способ (ADR-063); «Обновить» для устаревшего перезагружает **только уже загруженные типы** (2.0.0-beta.4); «Обновить с перезаписью параметров» — для всех загруженных типов (#239).
- **DnD в проект**: перетаскивание из панели в окно Revit с размещением в точке drop, возврат фокуса, кэш файлов (2.0.0-beta.1); DnD stale-типа → свежая версия из каталога (beta.8).
- Статистика использования пишется FireAndForget (не блокирует загрузку). Единый диалог загрузки shared nested (ADR-029) с прогрессом «Shared nested N of M».

### 1.13 Actualization engine

- **«Обновить базу»** (ADR-054, Phase — beta.5): реестр задач `IDatabaseActualizationTask` (детект по пустоте колонок, идемпотентность, маркеры ошибок), каждый файл открывается **ровно один раз**; critical-задачи блокируют базу на запись (жёлтый баннер + гейт-диалог с версией Revit), optional — янтарная точка (краснеет при critical); один modeless прогресс + одна сводка с очисткой.
- Задачи на текущий момент: `hash-v3` (critical, заменила `hash-v2`), `attributes-v1`, `glb-v1`, `family-facts-v1`, `revit-category-v1`, `mini-project-marker-v1`. Read-only режим при pending: все команды записи блокируются, view-only доступны (beta.3). Повреждение тестовой базы — `tools/damage-catalog-db.ps1`.

### 1.14 Поиск, теги, дерево

- Поиск с debounce 300 мс, авто-раскрытие категорий и подсветка совпадений, восстановление состояния раскрытия, скрытие пустых категорий; лимит 500 элементов снят (v1.8.1-beta.2/2.0.0-beta.4).
- **Быстрый поиск по имени ИЛИ тегу**: токены через И, внутри токена ИЛИ, до 3 совпавших чипов тега в строке (beta.5); редактор тегов — WrapPanel, фикс запятой в RU-раскладке.
- Дерево: DnD реорганизация категорий и семейств (в т.ч. drop на раскрытую категорию → в родителя, ADR-019), sticky-заголовки категорий (ADR-038), развернуть/свернуть всё (одна кнопка), Shift+колесо — горизонтальный скролл, защита от случайного DnD при прокрутке (#236), подавление горизонтального скролла на длинных именах, «Найти в каталоге» для выделенного в Revit, пустые категории видны.

### 1.15 UI-паттерны

- **StatusNotice / StatusDetailsView** (ADR-066 §E3, Phase 36): единый паттерн кликабельных статус-бэйджей (title + буллеты имён + guidance), два вида диалога — problem (warning/error + действия) и info (связи); сплит-кнопка «Обновить ▾» по канону DbTools. Заменил зоопарк из 5 некликабельных значков. **Это канон для облачных «Доступны обновления»** (уже заложено в ADR-075 §6).
- Баннеры: жёлтый баннер pending-обновления (primary), красная/янтарная точка в меню инструментов базы; баннер «обновите плагин» (forward-compat).
- Modeless-диалоги с прогрессом: batch import (ADR-048), миграции/актуализация (ADR-050/054). Подтверждение закрытия при несохранённых изменениях (`ISaveableViewModel`+`DialogCloseHelper`, v1.9.3-beta.4). Комбо с подтверждением, единые OK/Cancel Enter/Escape.
- Локализация RU/EN — единый SSOT, модульная декомпозиция, LocExtension (net48-фикс ContextMenu/Popup), ADR-020.

### 1.16 Multi-version (R19–R26)

- Поддержка Revit 2019–2026: net48 (2019–2024) + net8.0-windows (2025–2026); конфигурации R19/R21/R24/R25(/R26). Изоляция зависимостей (ADR-051): ILRepack → `SmartCon.Dependencies` на net48 и R25, самовосстанавливающийся `.addin`. Кросс-версионные хелперы: `RevitUnitsCompat`, `ElementId` по версиям, условный `AdWindows.dll` (`NO_ADWINDOWS`), рефлексия для `GetSpecTypeId`/`GetDataType`.

## 2. Поверхности интеграции для облачной фичи (гейтинг read-only)

### Пишут в БД и/или файлы (должны блокироваться для read-only облачной копии)

| Команда / флоу | Что пишет |
|---|---|
| Пакетный импорт (UC-1…UC-4), «Новая версия», «Перезаписать текущую» | `catalog_items/versions/files/types/attributes`, managed `.rfa`/`.rvt`, GLB, `family_dependencies`, ES-маркер в проекте |
| Обновить / Обновить с перезаписью параметров / Перезаписать Type Catalog | Файл версии, типы/атрибуты, хэш, ES-маркер, проект (system sync на месте) |
| SetActiveVersion, удаление версии | `catalog_versions`, `family_types` (FK CASCADE), имя элемента |
| Удаление семейства / категории (Dependency Guard) | Строки БД + managed-файлы (fail-fast: сначала файлы) |
| Редактор категорий (full-immediate), привязки атрибутов | Категории, bindings — сразу, без OK |
| Редакторы правил: validation (ADR-059), auto-assignment (ADR-070) | `category_validation_rules`, `category_assignment_*` |
| Свойства семейства (Save): имя/статус/теги/описание, переименование файла | `catalog_items`, managed-файл (rename) |
| Assets: добавить/удалить/сделать основным/привязать к версии; Avatar crop | `family_assets`, файлы assets, производный `avatar.png` |
| «Обновить базу» (actualization engine), миграции хэшей | Любые колонки/таблицы + пересчёт хэшей, GLB, маркеры |
| Управление базами: создать/подключить/удалить/конвертировать тип, правила привязки | `registry.json`, `database_meta`, файлы базы |
| Purge | Строки БД всегда; директории best-effort |
| Metadata package: импорт | Атомарный коммит категории+атрибуты+правила |
| RBAC: управление пользователями | `db_users` |
| LoadToProject / Place / DnD в проект | **Не БД**, а проект: ES-маркер, элементы; usage-статистика в БД (FireAndForget) |
| 3D on-demand extraction (нет GLB) | GLB-asset в managed storage |

### Только читают (безопасны для read-only копии)

Дерево/поиск/теги, свойства (просмотр), вкладки Версии/Атрибуты/Содержимое, 3D-просмотр существующего GLB, тултипы/аватары, «Найти в каталоге», StatusDetails-диалоги, «Проверить» (сверка проект↔каталог), metadata package **экспорт**, профиль (просмотр).

**Существующие гейты, на которые облако должно опереться:** RBAC CanExecute, read-only при pending critical-актуализации (жёлтый баннер + `IDatabaseUpdateStateService`), forward-compat гейт `min_plugin_version` (ADR-058), Engineer `Mode=ReadOnly` SQLite, Dependency Guard, stale-сторож «никогда не размещать stale».

### Ломающие изменения и как выкатывались

- **2.0.0 (stable, 2026-07-07)**: жёсткий разрыв — каталоги <2.0.0 несовместимы (per-version типы, content-hash, новые пути, shared-nested таблица). Без DDL-миграции: пользователь создаёт новый каталог и реимпортирует; откат на 1.9.3 через Updater. Выкат через 4 beta (beta.1→beta.4), 45+ issues.
- **Hash v2 → v3 (ветка 2.0.1-beta, «breaking 3.0.0» в терминах Phase 32/33)**: мягкий разрыв без потери базы — user-initiated пересчёт хэшей через actualization engine (modeless прогресс, докачка), база read-only до завершения; forward-compat `min_plugin_version` (V24) ретро-гейтит FHV3-базы на 2.0.1-beta.5 — старый плагин видит баннер «обновите плагин» вместо порчи данных (ADR-058, #173).
- Удалённые команды в 2.0.0: «Импорт папки», «Импорт данных» (покрыто batch-импортом); переименования: «Инкремент версии»→«Новая версия», «Импорт системного семейства»→«Импорт выделенных элементов».
